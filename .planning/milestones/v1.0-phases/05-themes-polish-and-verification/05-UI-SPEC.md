# Phase 05 — UI Design Contract

> Visual and interaction contract for Phase 05: Themes, Polish, and Verification. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — existing custom token system |
| Preset | not applicable |
| Component library | none/custom React components |
| Icon library | `lucide-react` |
| Font | Local Inter Variable for UI, local JetBrains Mono Variable for timeline/code/JSON |

### Existing UI Architecture Locked for This Phase

- `packages/ui/src/styles/tokens.css` is the single source of truth for theme color, shadow, spacing, typography, and effect values.
- `packages/ui/src/styles/global.css` may apply semantic token-based global effects, JSON classes, focus rings, media queries, and reduced-motion rules.
- Components must use semantic tokens/classes only. Components must not introduce raw color literals, including:
  - `#hex`
  - `rgb(...)`
  - `rgba(...)`
  - `hsl(...)`
  - `hsla(...)`
  - raw color values embedded in `boxShadow`, gradients, borders, SVG fills/strokes, or inline style strings
- Raw color values are permitted only in `tokens.css`.
- Component shadow values must be tokenized. Replace the current header menu `rgba(0,0,0,0.35)` shadow with `var(--shadow-menu)` or an equivalent token.
- No CDN assets, telemetry, external runtime calls, remote fonts, or third-party registries are allowed for Phase 05 UI polish.
- `components.json` is not present. Do not initialize shadcn for this phase; the project already has a token-first custom design system that Phase 05 must harden.

## Spacing Scale

Declared values must be multiples of 4 and map to existing or new CSS tokens in `tokens.css`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, row rail width, resize handle width, tight menu offsets |
| sm | 8px | Compact element spacing, row horizontal padding, JSON padding starts |
| md | 16px | Default element spacing, keyboard resize increment, drawer internal gap |
| lg | 24px | Section padding, detail empty/error state padding, drawer edge padding |
| xl | 32px | Layout gaps, major panel spacing |
| 2xl | 48px | Major section breaks, empty state vertical rhythm |
| 3xl | 64px | Page-level spacing where available |

### Fixed Density Values

| Token / Value | Contract |
|---------------|----------|
| `--row-height: 28px` | Timeline event and parse-error rows remain 28px tall for dense scanning. |
| `--row-group-header-height: 24px` | Group headers remain 24px tall. |
| `--row-banner-height: 20px` | Gap/inline timeline banners remain 20px tall. |
| `--filter-bar-height: 40px` | Desktop single-row filter bar target height. May expand to wrapped rows at responsive breakpoints. |
| `--filter-chips-height: 32px` | Active chip row target height. |
| 44px | Minimum touch target for overlay drawer close button, theme picker button at narrow widths, and any icon-only responsive control. |

Legacy note: existing `--space-3` / 12px usage may remain only where already present until touched. New Phase 05 spacing decisions must use the standard scale above; when a touched component needs nearby spacing, migrate to 8px or 16px instead of adding new 12px usage.

## Typography

Use exactly these 4 UI sizes and 2 font weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro label / metadata | 12px | 400 or 600 | 16px |
| Dense UI / timeline row | 13px | 400 or 600 | 20px |
| Body / empty state body | 14px | 400 | 21px |
| Heading / panel title | 16px | 600 | 20px |

### Typography Rules

- Weights are limited to:
  - regular: `400`
  - semibold: `600`
- Timeline, timestamps, IDs, latency, payload previews, Pretty JSON, and Raw JSON use `var(--font-mono)` where already established.
- General chrome, filters, menus, banners, picker, and detail summary labels use `var(--font-sans)`.
- Do not add display typography above 16px in Phase 05; this is a dense developer tool, not a marketing surface.
- Body copy line-height target is 1.5 (`14px / 21px`).
- Heading line-height target is 1.25 (`16px / 20px`) to preserve compact panel density.

## Theme Direction

### Dark Theme Final Direction

Dark is the default baseline through `:root, [data-theme="dark"]`.

| Area | Contract |
|------|----------|
| Overall feel | Matte dark developer tool; calm, high legibility, low glare. |
| Dominant | `--color-bg: #0e1116` remains the base canvas. |
| Secondary | `--color-surface: #161a21`, `--color-surface-raised: #1c2129` remain the chrome/panel family. |
| Accent | `--color-accent: #7aa2f7` remains the precise blue focus/selection accent. |
| Timeline | Selected row uses `--row-selected-bg`, not generic raised surface alone. Hover uses `--row-hover-bg`; hover must be subtler than selection. |
| Filters | Filter chips must read as controls without glowing; active chips may use accent-tinted chip background. |
| Detail panel | Detail side rail uses `--color-surface`; Summary and AHP field strips use raised/chip surfaces. |
| JSON | JSON key/string/number/boolean/null colors remain distinct and readable on `--color-json-bg`. |
| Banners | Rotation and watch-error banners use semantic token blends from `tokens.css`, not component color functions. |
| Status bar | Muted metadata on surface; paused state uses `--color-status-paused-*`. |

### Light Theme Final Direction

Light theme must feel intentionally polished, not a washed-out inversion.

| Area | Contract |
|------|----------|
| Overall feel | Crisp paper-like canvas with clear borders and high text contrast. |
| Dominant | `--color-bg: #f7f8fb` or an equivalent very-light cool surface. |
| Secondary | `--color-surface: #ffffff`, `--color-surface-raised: #f0f3f8`. |
| Accent | `--color-accent: #245fc7` or an equivalent blue that passes contrast on white and light raised surfaces. |
| Timeline | Row boundaries must remain visible through border/hover/selected tokens. Selected row cannot rely on rail only; use a visible but subtle `--row-selected-bg`. |
| Filters | Search field, chips, popovers, active chip row, and disabled Turn chip must each have visible contrast against white surfaces. |
| Detail panel | Border between timeline and detail must be at least `--color-border-strong`. Summary fields must not appear as pale-on-white chips. |
| Pretty JSON | JSON strings, numbers, booleans, nulls, punctuation, and keys must pass contrast against `--color-json-bg`. Yellow warning/number colors must be dark enough for white surfaces. |
| Raw JSON | Monospace text uses `--color-text`; no low-contrast muted raw payload text. |
| Banners | Rotation, watch-error, gap, auth-failure, and truncation banners must be visibly tinted but preserve readable text. |
| Theme picker | Menu shadow/border must separate from white header. Active menu item must be distinguishable without relying only on the check icon. |
| Status bar | Muted text must remain readable; connection states cannot be color-only. |

Light theme contrast target:
- Normal text: WCAG AA 4.5:1 minimum.
- 12px metadata and row labels: WCAG AA 4.5:1 minimum.
- Non-text controls/focus/rails: WCAG AA 3:1 minimum.
- Do not use color-only state changes; pair color with text, icon, glyph, rail, or pill label.

### Hacker Theme Final Direction

Hacker mode must go all out while remaining usable for dense log reading.

| Area | Contract |
|------|----------|
| Overall feel | Full CRT terminal aesthetic: phosphor green base, cyan/yellow/purple/red retrowave accents, scanlines, subtle grid/noise, glow, sharper terminal borders. |
| Dominant | `--color-bg: #020704` or equivalent near-black green. |
| Secondary | `--color-surface: #06120a`, `--color-surface-raised: #0a1b10`, with terminal-like borders. |
| Accent | `--color-accent: #39ff88` phosphor green. |
| Additional accents | Cyan for server/client contrast and JSON numbers, yellow for warning/string emphasis, purple for action/boolean, red-pink for destructive/error. |
| Timeline | Dense row text must stay readable: primary row text should not have heavy text-shadow. Glow belongs on rails, borders, selected row halo, active chips, picker dot, and focus ring. |
| Selection | Selected row uses `--row-selected-bg`, accent rail, and optional tokenized glow. Focus ring must be highly visible and not hidden by scanlines. |
| Background effects | Apply scanline/grid/noise overlays globally with pseudo-elements or background layers in `global.css`, controlled by tokens. Effects must not intercept pointer events. |
| CRT effects | Static scanline overlay, faint grid, phosphor glow, terminal border highlights, subtle vignette are allowed. |
| Motion | Optional slow scanline drift/flicker is allowed only when `prefers-reduced-motion: no-preference`. Reduced-motion users get static/no-animation equivalents. |
| JSON syntax | Hacker JSON colors must be deliberately cyberpunk: key green, string yellow, number cyan, boolean purple, null muted green, punctuation muted phosphor. |
| Filters | Active chips may glow; inactive chips must remain subdued. Popovers must not become translucent enough to reduce option readability. |
| Banners | Errors/destructive remain red-pink and must overpower decorative green. Rotation/warning remains yellow. |
| Detail panel | Pretty/Raw tabs and copy menu should look terminal-like but preserve current tab state clearly. |
| Text selection | Use `--selection-bg` and `--selection-fg`; selected text must be readable over hacker surfaces. |

#### Hacker Maximum Effect Boundaries

The following are hard limits:

- Scanline opacity must not exceed 0.14.
- Grid opacity must not exceed 0.10.
- Noise opacity must not exceed 0.06.
- Text glow on dense timeline body text must be none or effectively imperceptible.
- Animated flicker must not change text position, row height, column width, scroll position, or virtualization measurement.
- No effect may introduce layout shift.
- No effect may reduce normal text below WCAG AA contrast.
- No effect may obscure selected row, focus ring, parse-error row, auth-failure banner, or watch-error banner.
- Reduced-motion mode disables animation; static scanline/grid/noise may remain only if readability is unchanged.

## Theme Picker Contract

### Placement

- The compact theme picker remains in the top-level `HeaderBar`, to the right of live/switch-log controls and before the version label.
- The top-level control remains compact: icon + current theme accent dot + chevron.
- Do not show the labels “Dark”, “Light”, or “Hacker” directly in the header. Labels are hidden behind the compact picker menu.

### Button Copy and Accessibility

| Element | Exact copy / attribute |
|---------|------------------------|
| Button accessible name | `Theme picker (Dark)`, `Theme picker (Light)`, or `Theme picker (Hacker)` |
| Button title | `Theme: Dark`, `Theme: Light`, or `Theme: Hacker` |
| Menu accessible label | `Theme` |
| Dark option | `Dark` |
| Light option | `Light` |
| Hacker option | `Hacker` |

### Behavior

- Click or Space/Enter on the button toggles the menu.
- Menu uses `role="menu"` with `role="menuitemradio"` options.
- Current theme option exposes `aria-checked="true"` and a visible check icon.
- Selecting an option:
  1. sets `document.documentElement.dataset.theme`
  2. writes `localStorage["ahp-theme"]`
  3. closes the menu
  4. returns focus to the theme picker button
- Escape closes the menu and returns focus to the theme picker button.
- Click outside closes the menu.
- Up/Down arrows move active option focus inside the menu.
- Home/End jump to first/last option.
- If localStorage is unavailable or throws, apply the selected theme for the current page and fail silently.
- Invalid stored theme values fall back to `dark`.

## Responsive Layout Contract

### Breakpoints

| Range | Name | Detail behavior | Timeline behavior |
|-------|------|-----------------|-------------------|
| `< 768px` | narrow | Detail opens as full-height overlay drawer, width `100vw`, close button required. | Timeline remains primary; horizontal overflow allowed inside timeline viewport. |
| `768px – 1399px` | laptop | Detail opens as overlay drawer, width `min(88vw, 720px)`, backdrop required. | Timeline must not be squeezed by detail. |
| `>= 1400px` | desktop | Detail appears as side rail, default 420px, resizable 360–720px. | Timeline and detail share main split. |
| `>= 1920px` | wide | Detail side rail remains max 720px; timeline absorbs useful payload width. | Avoid empty “ocean” by keeping chrome/panel widths bounded and payload column useful. |
| `>= 2560px` | ultra-wide | Main app may use full width, but detail rail still maxes at 720px and filter/picker popovers remain anchored. | Payload column can expand; fixed scan columns do not stretch. |

### Detail Panel / Drawer

Desktop side rail:
- Render as a right-side `<aside aria-label="Event detail">`.
- Width default: 420px.
- Resizable min/max: 360px–720px.
- Keyboard resize increments: 16px.
- Detail rail must not be rendered in the layout split below 1400px.

Laptop/narrow overlay drawer:
- Selecting a timeline row opens the detail drawer.
- Drawer side: right.
- Width:
  - `<768px`: `100vw`
  - `768px–1399px`: `min(88vw, 720px)`
- Backdrop uses `--overlay-backdrop`.
- Drawer shadow uses `--shadow-drawer`.
- Drawer border uses `--drawer-border`.
- Drawer close control:
  - visible at the top-right of the drawer
  - accessible name: `Close details`
  - minimum target: 44px by 44px
- Escape closes the drawer when focus is inside the drawer or the drawer is open.
- Closing the drawer clears the selected event only if that is the existing app model chosen by implementation; otherwise it may keep `selectedIdx` while hiding the drawer. The UI must not leave an inaccessible offscreen detail panel.
- Focus:
  - On open, focus moves to the drawer container or close button.
  - On close, focus returns to the selected timeline row if it still exists; otherwise focus returns to the timeline region.
- Resize handle is hidden in overlay drawer mode.

### Filter Bar

Desktop (`>=1200px`):
- Filter bar stays one row when space permits.
- Search input keeps a minimum usable width of 280px.
- Facet chips do not shrink below readable labels.
- Group toggle and result counter remain right-aligned.

Laptop/tablet (`768px–1199px`):
- Filter bar may wrap to two rows.
- Search input occupies the first available row and remains at least 240px wide.
- Facet chips wrap as a group; popovers remain anchored to their triggering chip.
- Result counter may wrap to the end of the second row.
- No chip may be clipped by the viewport.

Narrow (`<768px`):
- Search input remains first.
- Facet chip group may horizontally scroll within the filter bar if wrapping would consume excessive vertical space.
- Horizontal chip scrolling must not scroll the timeline.
- Popovers must stay within viewport bounds.

### Timeline Horizontal Overflow

- Timeline has a minimum inner grid width based on `TIMELINE_GRID_COLUMNS`.
- Header and rows must share the same grid width at all viewports.
- If viewport width is insufficient, horizontal overflow belongs inside the timeline scroll container, not the page body.
- Column labels must stay aligned with row cells during horizontal scroll.
- Detail overlay must not introduce additional horizontal body scroll.
- Do not shrink timestamp, direction, kind, status, latency, or ID columns below their current scan widths.
- Payload preview is the only column that should absorb extra width.

## Persistence Contract

| Property | Contract |

- `searchQuery`
- `filters`
- `grouping`
- `groupCollapsed`
- `selectedIdx`
- `detailWidth`
- `livePaused`

Rules:
- Keep max 50 remembered logs.
- Keep collapsed group cap at 1000.

- Do not add new persisted preferences unless a new explicit UI preference control is introduced.
- Detail drawer open/closed state should not be persisted unless a concrete UI preference is added and approved.

## Accessibility Contract

### Keyboard

- Theme picker:
  - Enter/Space toggles menu.
  - Up/Down navigates menu options.
  - Home/End jumps first/last.
  - Enter/Space selects.
  - Escape closes and returns focus to button.
- Timeline:
  - Existing Up/Down/PageUp/PageDown/Home/End navigation remains.
  - `/` focuses search.
  - `Esc` clears search → clears filters → clears selection in sequence.
  - Space toggles live pause only when focus is not inside editable controls.
- Detail drawer:
  - Escape closes drawer.
  - Focus returns to selected row or timeline region.
  - Close button is keyboard reachable and named `Close details`.
- Resize handle:
  - Desktop only.
  - ArrowLeft increases detail width by 16px.
  - ArrowRight decreases detail width by 16px.
  - Accessible name remains `Resize detail panel`.

### Focus

- Global `:focus-visible` uses `--focus-ring` or `--color-accent`.
- Focus outline is 2px minimum with 2px offset.
- Hacker glow must not obscure focus rings.
- Focus must be visible on:
  - theme picker button
  - menu options
  - filter chips
  - popover controls
  - timeline region/rows
  - detail drawer close button
  - detail tabs
  - copy menu controls
  - retry/reconnect buttons

### Contrast

- Normal and dense text: minimum WCAG AA 4.5:1.
- Non-text indicators and focus rings: minimum WCAG AA 3:1.
- Light theme muted text must remain readable at 12px.
- Hacker scanlines/grid/noise cannot reduce effective text contrast below AA.
- Color cannot be the only indicator for errors, selection, active filters, or current theme.

### Reduced Motion

- Respect `prefers-reduced-motion: reduce`.
- Disable:
  - scanline drift
  - CRT flicker
  - pulsing glow
  - any animated grid/noise movement
  - spinner rotation where feasible, matching existing `.spin` reduced-motion behavior
- Static equivalents may remain if they do not reduce readability.

### ARIA

- Theme menu uses menu/menuitemradio semantics.
- Detail side rail/drawer uses `aside` or dialog-like semantics with `aria-label="Event detail"`.
- Overlay drawer backdrop must not trap screen reader focus outside the drawer if implemented as modal.
- Banners use alert/status semantics appropriate to urgency:
  - watch error: alert
  - rotation/new events: status or polite live region
- Icon-only controls require accessible labels.
