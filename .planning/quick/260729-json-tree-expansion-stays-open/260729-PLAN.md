# Quick Task 260729-json-tree-expansion-stays-open

## Description

When a user expands a JSON tree item in the request/response detail sidebar, it automatically collapses again as live timeline rows update. The expanded item must remain open so its contents can be read.

## Diagnosis

Verified against the installed `react-json-view-lite@2.5.0` source
(`node_modules/.pnpm/react-json-view-lite@2.5.0_react@19.2.6/node_modules/react-json-view-lite/dist/index.modern.js`):

`ExpandableObject` holds its own `expanded` state (`useState(() => shouldExpandNode(level, value, field))`)
and has this effect:

```js
const shouldExpandNodeCalledRef = useRef(false);
useEffect(() => {
  if (!shouldExpandNodeCalledRef.current) {
    shouldExpandNodeCalledRef.current = true;
  } else {
    setExpanded(shouldExpandNode(level, value, field));
  }
}, [shouldExpandNode]);
```

On first mount the guard ref skips the recompute. On every subsequent render where the
`shouldExpandNode` **function identity** changes, the effect fires and calls
`setExpanded(shouldExpandNode(...))`, overwriting whatever the user manually toggled via
`clickToExpandNode`.

`packages/ui/src/components/detail/PrettyJsonView.tsx` passes an inline arrow function as
`shouldExpandNode`:

```tsx
<JsonView
  data={data as object}
  shouldExpandNode={(level: number, value: unknown) =>
    hasQuery ? level < 1 || subtreeContainsQuery(value, query) : level < 5
  }
  ...
/>
```

This closure is re-created on every render of `PrettyJsonView`, so its identity changes every
time the component re-renders — even when `data` and `query` are unchanged. `DetailPanel.tsx`
re-renders on unrelated store changes (e.g. `rows` updates as live SSE events patch the
timeline), which cascades into `PrettyJsonView` re-rendering with a fresh `shouldExpandNode`
closure. That resets every manually expanded/collapsed node back to its `shouldExpandNode`
default, even though the user never touched selection or query.

Note: `DetailPanel` already remounts `PrettyJsonView` via `key={selectedIdx}:{query}...}` on
selection/query changes (see `DetailPanel.tsx` lines ~493-521, ~577-582), so that path is not
in scope — this is specifically about unrelated rerenders while the same node stays mounted.

The surgical fix is to stabilize the `shouldExpandNode` callback identity in `PrettyJsonView`
(e.g. `useCallback`/`useMemo` keyed only on `hasQuery`/`query`, the actual determinants of
expansion policy) so identity is stable across rerenders where those inputs are unchanged,
while preserving existing query-driven expansion semantics (level-based default, match-aware
auto-expand under `query`).

## Tasks

1. Add regression coverage in `packages/ui/src/components/detail/PrettyJsonView.test.tsx`:
   render `PrettyJsonView` with a nested object, click a collapsed-by-default node open (or
   collapse an expanded one) via its clickable label, then `rerender(...)` with the exact same
   `data`/`query` props (simulating an unrelated parent rerender, e.g. from a `rows` store
   update). Assert the manually-toggled expansion state is preserved (the toggled node's
   content is still visible/hidden as the user left it), not reset to the `shouldExpandNode`
   default. Also add a case confirming that changing `query` (a real, intentional input change)
   still recomputes expansion as expected, to guard against overcorrecting into a callback that
   never updates.

2. Update `packages/ui/src/components/detail/PrettyJsonView.tsx` so the `shouldExpandNode`
   function passed to `JsonView` has a stable identity across rerenders unless its actual
   determinants (`hasQuery`, `query`) change — e.g. wrap it in `useCallback` with dependencies
   limited to `hasQuery` and `query` (not recreated as a fresh inline arrow on every render).
   Keep the existing behavior unchanged: `hasQuery ? level < 1 || subtreeContainsQuery(value, query) : level < 5`.
   Do not touch `DetailPanel.tsx`'s `key={...}` remount behavior on selection/query change —
   that is correct and out of scope.

3. Verify with `pnpm -F @ahp-inspector/ui test -- PrettyJsonView.test.tsx` and
   `pnpm -F @ahp-inspector/ui typecheck`.

## Done When

- Manually expanding or collapsing a JSON tree node in the detail sidebar stays in that state
  across unrelated rerenders (e.g. live `rows` updates from SSE), instead of snapping back to
  the default/query-derived expansion.
- Existing match-aware auto-expand behavior (D-08/D-09: expanding to reveal a search match, or
  the level<5 default with no query) is unchanged when `query` or the selected event actually
  changes.
- `pnpm -F @ahp-inspector/ui test -- PrettyJsonView.test.tsx` and
  `pnpm -F @ahp-inspector/ui typecheck` both pass.
