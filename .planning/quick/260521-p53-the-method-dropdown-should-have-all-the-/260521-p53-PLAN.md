# Quick Task 260521-p53

## Description

The Method facet should behave like a visibility checklist: every discovered method is checked by default, unchecking a method hides rows for that method, and `ping` starts unchecked by default.

## Diagnosis

Current filter semantics treat every array facet as an inclusion list. In `packages/ui/src/state/filters.ts`, `filters.method = []` means “match all methods,” and `filters.method = ["initialize"]` means “show only initialize.” `FilterBar` passes that same array directly to `FacetPopover`, so unchecked currently means “not selected into an inclusion filter.”

For this request, only the Method facet should invert its meaning: the stored method array should represent hidden/excluded methods. That keeps the implementation small while letting the dropdown render all available methods as checked except methods in `filters.method`. The default store/reset state should exclude `ping` so ping rows are hidden until the user explicitly checks ping.

## Tasks

1. Update method filter semantics and defaults.
   - Files: `packages/ui/src/state/filters.ts`, `packages/ui/src/state/store.ts`, `packages/ui/src/persistence/persist-effect.ts`, and any tests that reset store filters directly.
   - Add an explicit default filter constant for the app view state, with `method: ["ping"]`, and use it for initial store state, `clearFilters()`, log-switch resets, and test resets where the expected user-facing default should apply.
   - Keep non-method facets as inclusion lists. Change only `applyFacets()` method handling so rows are hidden when `row.method` is in `filters.method`; rows with `method === null` should still pass the method exclusion filter.
   - Preserve `EMPTY_FILTERS` as the true no-filter/no-exclusion shape for tests or helper code that needs it, but do not use it as the normal app default after this change.

2. Wire the Method dropdown as a checked-by-default exclusion control.
   - Files: `packages/ui/src/components/filters/FilterBar.tsx`, `packages/ui/src/components/filters/FacetPopover.tsx`, `packages/ui/src/components/filters/ActiveFilterChips.tsx`.
   - In the Method facet, derive checked values from `facetCounts.method` by taking every available method except values in `filters.method`. On change, convert the checked list back to hidden methods and call `patchFilter("method", hiddenMethods)`.
   - Ensure opening the Method dropdown with rows containing `initialize` and `ping` shows `initialize` checked and `ping` unchecked by default.
   - Keep the generic `FacetPopover` behavior unchanged for all other facets. If footer wording needs to differ for Method, add optional props with current labels as defaults instead of hardcoding method-specific text into the generic component.
   - Update active filter chips for method exclusions so the label/aria text communicates hidden methods, for example `Hidden method: ping`, and dismissing that chip re-checks the method.

3. Add focused tests and run the UI verification gate.
   - Files: `packages/ui/src/state/selectors.test.ts`, `packages/ui/src/components/filters/FilterBar.test.tsx`, `packages/ui/src/components/filters/ActiveFilterChips.tsx` tests if needed.
   - Add selector tests proving the default filter hides `ping`, non-ping methods remain visible, explicitly adding another method to `filters.method` hides it, and null-method rows are not hidden by method exclusions.
   - Add FilterBar tests proving the Method popover renders all discovered methods checked except `ping` by default, and unchecking a checked method updates `filters.method` to include that method.
   - Run `pnpm -F @ahp-inspector/ui test -- FilterBar.test.tsx selectors.test.ts` and `pnpm -F @ahp-inspector/ui typecheck`.

## Done When

- The Method dropdown opens with all discovered methods checked except `ping`.
- Unchecking any checked method hides that method from the timeline by adding it to the method exclusion list.
- `ping` rows are hidden by default in normal app/reset/log-switch state, while users can check `ping` to show them.
- Other facet filters keep their existing inclusion-list behavior.
- Focused UI tests and typecheck pass.
