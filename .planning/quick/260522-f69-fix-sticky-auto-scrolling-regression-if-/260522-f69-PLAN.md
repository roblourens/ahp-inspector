# Quick Task 260522-f69

## Description

Fix sticky auto-scrolling regression: if a row is selected and the user scrolls to the bottom, appending rows should keep following the bottom instead of jumping back to the selected row or top.

## Diagnosis

`TimelineList` has two scroll effects: tail-follow on `items.length` changes, and selected-row centering when `selectedIdx` is off-screen. The selected-row effect depends on `items` and `rows`, so it re-runs when rows append even if the selection did not change. When the selected row is above the viewport, that effect disables tail-follow and scrolls back to the selection, overriding the expected bottom-follow behavior.

## Tasks

1. Add regression coverage in `packages/ui/src/components/timeline/TimelineList.virt.test.tsx` for this exact sequence: selected row exists above, user is at bottom, rows append, scroll remains at the new bottom.
2. Update `packages/ui/src/components/timeline/TimelineList.tsx` so selected-row centering only responds to actual selection changes, not ordinary row/item append updates.
3. Verify with `pnpm -F @ahp-inspector/ui test -- TimelineList.virt.test.tsx` and `pnpm -F @ahp-inspector/ui typecheck`.

## Done When

- Tail-follow continues to the new bottom while a stale selected row remains above the viewport.
- Changing selection still scrolls the selected row into view when it is off-screen.
- Existing off-bottom inspection behavior remains stable.
