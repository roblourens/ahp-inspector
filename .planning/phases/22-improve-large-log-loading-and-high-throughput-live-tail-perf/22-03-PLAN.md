`WatchSink` currently has `onChunk(bytes, byteOffset)`, `onReset(...)`, and `onError(...)`. `TailReader.readInitial()` already owns `sizeAtStart`; expose that fact through typed lifecycle callbacks instead of fabricating progress from row counts.
`SsePayload` currently includes snapshot begin/chunk/end, append, patch, ping, bye, rotation, watch-error, and log-reset. Extend this typed union with progress/backlog metadata beside rows, not inside `EventRow`.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem tail reader -> host watch sink | Local files can grow, rotate, or error while progress is observed. |
| server AppState -> SSE browser transport | Progress/backlog metadata crosses the local loopback stream boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-03-01 | I | Progress/backlog payloads | mitigate | Emit byte counts, row counts, and basename-safe existing metadata only; never raw paths or raw event contents. |
| T-22-03-02 | D | SSE queue during baseline snapshot | mitigate | Subscribe before concurrent frames can be lost, drain bounded queued payloads, and surface backlog count instead of hiding lag. |
| T-22-03-03 | T | Percent calculation | mitigate | Base percentages on captured initial-read byte totals; omit percentages when no trustworthy denominator exists. |
</threat_model>
