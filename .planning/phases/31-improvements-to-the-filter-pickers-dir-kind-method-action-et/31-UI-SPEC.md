**Phase 31 supersession rule:** This contract supersedes Phase 25 only where Phase 25 requires `Select all` and `Uncheck all` to appear simultaneously. Phase 31 requires exactly one contextual command and removes the visible `Close` action. Every other Phase 25 picker behavior remains binding.

## Experience Intent

The facet menus are dense operational controls in a developer tool. They must feel predictable while a user scans and filters live traffic: option targets stay in stable alphabetical positions, the footer presents one truthful next action, and full-width controls remain visibly contained by their raised surfaces. This phase is polish over the existing visibility model, not a new filtering model or picker redesign.

### User-Visible Truths

- Each categorical facet menu shows exactly one bulk command: `Uncheck all` only when every complete option is checked; otherwise `Select all`.
- The contextual command always affects the complete facet option set, including options hidden by a local picker query or beyond the first 100 rendered rows.
- The default Method menu has `ping` unchecked and therefore initially offers `Select all`.
- No categorical facet menu shows a visible `Close` action. Clicking the open facet trigger again or clicking outside closes it.
- Dir, Kind, Method, Action, Channel, Turn, and Status option rows are sorted alphabetically by the visible label, case-insensitively. Raw value breaks visible-label ties. Counts remain visible but never determine order.
- The searchable Method, Channel, and Turn inputs remain fully inside the picker surface at all supported widths.
- The selected row/background in the `Group: Session` picker remains fully inside the grouping surface.
- Checkbox meaning, active chips, persisted filters, default-hidden `ping`, local query behavior, 100-row cap, all themes, and local-only fixture evidence remain unchanged.

## Layout And Control Geometry

| Surface | Contract |
|---------|----------|
| Facet trigger | Preserve existing 28px chip height, compact spacing, active/open treatment, and anchor position. |
| Facet popover | Preserve raised surface, 6px radius, 180px minimum width, 320px maximum width, 320px maximum height, vertical scrolling, and `var(--shadow-menu)`. |

## Interaction Contract

### Contextual Complete-Facet Toggle

| Complete Facet State | Visible Footer Command | Action Result |
|----------------------|------------------------|---------------|
| Every complete option is checked/visible | `Uncheck all` | Uncheck/hide every complete option. |
| One or more complete options are unchecked/hidden | `Select all` | Check/show every complete option. |
| Default Method state with `ping` hidden | `Select all` | Reveal `ping` and every other complete Method option. |
| No complete options | Disabled `Select all` | No state change; empty copy remains `No options`. |

- Derive command state and action from the complete `options` set only, never the query-filtered set or first 100 rendered rows.
- The command label must not change when the local query changes; it changes only when complete-set checked state changes.
- Clicking the command does not close the popover. The changed checkbox state and flipped command label provide immediate feedback.
- Checked continues to mean visible. Stored filter arrays continue to represent hidden values; Phase 31 must not expose or invert that storage detail.
- Newly discovered values remain checked/visible unless explicitly hidden under the existing persistence contract.

### Deterministic Option Ordering

- Apply one ordering policy to Dir, Kind, Method, Action, Channel, Turn, and Status.
- Sort ascending by the user-visible label, case-insensitively; compare raw `value` ascending to break equal/case-colliding visible labels.
- Sort formatted Channel labels after formatting, not raw channel/session values.
- Keep counts visible at the right edge, but never use count or row-arrival order as a primary or tie-break sort key.
- Local query filtering preserves the relative alphabetical order of matching options.
- Live count changes must not move existing option targets. A newly discovered value enters at its alphabetically correct position.
- Time range and Group mode controls are not categorical facets and do not adopt this sorting policy.

### Open And Close Behavior

| Input / Action | Result |
|----------------|--------|
| Click a closed facet trigger | Open its facet popover. |
| Click the same open facet trigger | Close its facet popover. |
| Click outside the open facet popover | Close its facet popover. |
| Click checkbox or contextual command | Keep the facet popover open and update visible state. |
| Visible `Close` command | Must not exist. |
| Escape | No new Phase 31 behavior; preserve current behavior and defer a coordinated keyboard model. |

Removing the visible `Close` action must not remove or regress trigger-toggle and click-outside closure. Do not add a role-only ARIA change or an isolated Escape listener in this phase.

### Searchable Facet Query And Cap

- Method, Channel, and Turn retain their local query inputs; query matching remains literal and case-insensitive over visible label and raw value.
- Querying narrows only rendered picker options. It does not modify timeline filters or the complete-set bulk target.
- Preserve the 100-row rendered cap and `…and {N} more` status.
- Input border, background, text, and focus outline remain visibly inside the popover at desktop and narrow widths.

### Group Picker Geometry

- Group modes and labels remain `None`, `Session`, and `Session + Turn`; selection still closes the grouping popover.
- The selected radio row continues to use `var(--color-chip-bg-active)` across its full available width.
- The selected background, row padding, and full-width click target must end inside the popover border; no color or hit area may overflow horizontally.
- This is a local geometry correction only. Do not rename Group labels, reorder modes, or change radio selection behavior.

## Accessibility And Feedback

- Preserve native inputs, buttons, checkboxes, radios, labels, accessible names, and current 2px `var(--color-accent)` keyboard-focus treatment.
- The single contextual bulk command remains visible text because its meaning cannot be conveyed by a familiar icon alone.
- Keep checkbox labels and counts on one legible row; do not rely on color alone to communicate checked-visible state.
- Removal of visible `Close` leaves trigger-toggle and click-outside closure as the Phase 31 contract. Escape-to-close and the picker's ARIA/keyboard model require a coordinated follow-up and are explicitly out of scope unless a checker identifies a blocker.
- Do not change `role`, `aria-haspopup`, focus management, or keyboard semantics in isolation. A role-only change is not an accessibility fix.
