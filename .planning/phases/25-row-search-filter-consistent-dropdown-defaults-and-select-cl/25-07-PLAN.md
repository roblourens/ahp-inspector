# Gap-Closure Plan 25-07: Preserve v1 Hidden Method Preferences + Add Regression Test

**Origin:** The `migrateV1Filters()` function in persistence.ts line 83 discards any legacy `filters.method` array and resets it to `APP_DEFAULT_FILTERS` (method: ["ping"]). This causes data loss when users upgrade from v1 with custom hidden Method choices like ["ping", "some_custom_method"].

**Contract:** `.planning/phases/25-row-search-filter-consistent-dropdown-defaults-and-select-cl/25-UI-SPEC.md` (section "User-Visible Truths": "Every categorical popover presents checked-as-visible state, including `ping` unchecked on initial defaults").

**Behavioral Requirement:** v1 logs with custom hidden Method values must preserve those values during v1→v2 migration; the default `ping` unchecked state applies only on fresh logs without prior v1 preferences.

---

## Task Breakdown

### T1: Fix migrateV1Filters() to Preserve Legacy Method Array
**Status:** MUST (blocks data preservation)  
**Scope:** Modify `packages/ui/src/state/persistence.ts` lines 83-91 (migrateV1Filters function)  
**Current Behavior:**
```typescript
function migrateV1Filters(value: unknown): FilterState {
  if (!value || typeof value !== "object") return APP_DEFAULT_FILTERS;
  const filters = value as Record<string, unknown>;
  return {
    ...APP_DEFAULT_FILTERS,  // PROBLEM: overwrites all filter arrays with defaults
    timeFrom: filters.timeFrom === null || typeof filters.timeFrom === "number" ? filters.timeFrom : null,
    timeTo: filters.timeTo === null || typeof filters.timeTo === "number" ? filters.timeTo : null,
  };
}
```

**Required Changes:**
- Extract `filters.method` from v1 data if present and is a valid string array
- Validate: must be `Array.isArray(filters.method) && filters.method.every(item => typeof item === "string")`
- If valid, use the legacy `filters.method` array; otherwise, fall back to `APP_DEFAULT_FILTERS.method`
- Apply the same preservation logic to ALL categorical filter arrays: `direction`, `kind`, `method`, `actionType`, `session`, `turn`, `status`
- Preserve `timeFrom` and `timeTo` as currently implemented

**Acceptance Criteria:**
- Legacy v1 preferences with custom hidden Method choices (e.g. ["ping", "trace"]) are preserved as-is after migration
- Missing or invalid array fields fall back to app defaults (e.g., if method is undefined, use APP_DEFAULT_FILTERS.method)
- All existing v1→v2 migration tests continue to pass
- TypeScript type safety: `filters.method` is validated before use

**Code Pattern:**
```typescript
function migrateV1Filters(value: unknown): FilterState {
  if (!value || typeof value !== "object") return APP_DEFAULT_FILTERS;
  const filters = value as Record<string, unknown>;
  
  // Helper: validate and extract array field, or return default
  const extractFilterArray = (field: unknown, defaultValue: string[]): string[] => {
    if (Array.isArray(field) && field.every((item) => typeof item === "string")) {
      return field;
    }
    return defaultValue;
  };
  
  return {
    direction: extractFilterArray(filters.direction, APP_DEFAULT_FILTERS.direction),
    kind: extractFilterArray(filters.kind, APP_DEFAULT_FILTERS.kind),
    method: extractFilterArray(filters.method, APP_DEFAULT_FILTERS.method),
    actionType: extractFilterArray(filters.actionType, APP_DEFAULT_FILTERS.actionType),
    session: extractFilterArray(filters.session, APP_DEFAULT_FILTERS.session),
    turn: extractFilterArray(filters.turn, APP_DEFAULT_FILTERS.turn),
    status: extractFilterArray(filters.status, APP_DEFAULT_FILTERS.status),
    rowText: typeof filters.rowText === "string" ? filters.rowText : APP_DEFAULT_FILTERS.rowText,
    timeFrom: filters.timeFrom === null || typeof filters.timeFrom === "number" ? filters.timeFrom : null,
    timeTo: filters.timeTo === null || typeof filters.timeTo === "number" ? filters.timeTo : null,
  };
}
```
