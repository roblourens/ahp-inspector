# Gap-Closure Plan 25-06: SearchPopover/SearchTrigger UI Refactor + Toolbar Layout

**Origin:** User rejected the side-by-side Search input (flex) and RowFilterInput (280px) composition in Phase 25 verification as "ugly". Approved design: Filter rows as primary visible input; Search behind a popup trigger button.

**Contract:** `.planning/phases/25-row-search-filter-consistent-dropdown-defaults-and-select-cl/25-UI-SPEC.md` (revised 2026-05-30, lines 78-134 layout geometry).

## Task Breakdown

### T1: Create SearchPopover Component
**Status:** MUST (blocks all other UI tasks)  
**Scope:** New file `packages/ui/src/components/filters/SearchPopover.tsx`  
**Acceptance Criteria:**
- Popover container with `position: absolute`, `minWidth: 320px`, `maxWidth: 400px`, `var(--shadow-menu)`, 6px border-radius
- Renders full-width Search input inside (reuse SearchInput core input element, but without flex wrapper)
- Status line displaying match count: `{N} of {M} matches` or `{M} matches` when no selected match
- Prev/Next navigation buttons styled as secondary controls
- Closes on Escape key
- Remains fully within viewport on narrow widths
- Uses semantic color tokens (no new colors; reuse `--color-surface-raised`, `--color-border-strong`, `--color-text-muted`)

**Related Code to Extract:**
- SearchInput.tsx lines 45-95: input element styling (will become inline inside popover)
- FilterBar.tsx lines 68-80: existing search query state management (no new state; use existing store)

---

### T2: Create SearchTrigger Button Component
**Status:** MUST (blocks FilterBar refactor)  
**Scope:** New file `packages/ui/src/components/filters/SearchTrigger.tsx`  
**Acceptance Criteria:**
- Compact button: `height: 28px`, `minWidth: fit-content`, secondary button styling, lucide Search icon (16px) + "Search" label
- Accepts `isActive: boolean` prop; when true, displays subtle active indicator (accent border or background tint per UI-SPEC)
- Accessible label: "Open search"
- onClick handler: accepts `onToggle: () => void` callback; parent (FilterBar) manages popover visibility
- Width adapts to content (~80px typical)
- Uses semantic color tokens

**Styling Baseline:**
- Leverage existing compact button patterns from FacetChip (28px height)
- Border-radius: 4px (compact control)
- Consistent with TimeRangePopover trigger styling

---

### T3: Refactor FilterBar Layout
**Status:** MUST (unblocks toolbar composition)  
**Scope:** Modify `packages/ui/src/components/filters/FilterBar.tsx` (current lines 1-180+)  
**Acceptance Criteria:**
- Remove side-by-side SearchInput and RowFilterInput mounts (old lines ~6-9)
- Mount RowFilterInput with `flex: 1 1 auto`, `minWidth: 200px`, `maxWidth: 480px` (sole flexible primary input)
- Mount SearchTrigger button immediately after RowFilterInput (compact, 28px, adjacent)
- Add state: `isSearchPopoverOpen: boolean` + `setIsSearchPopoverOpen()` hook
- Conditionally render SearchPopover below toolbar when `isSearchPopoverOpen === true`
- Pass existing `searchQuery`, `setSearchQuery`, `searchMatches`, `selectedIdx`, and navigation callbacks to SearchPopover
- All existing facet chips and time-range popover remain unchanged
- Active chip strip and "Clear all" remain unchanged

**Layout Verification:**
- Desktop: Filter rows input, Search trigger button, facet chips, time range, results counter all coherent in 40px-height toolbar
- Narrow (e.g. 600px viewport): controls remain legible, Search popover does not overflow viewport

---

### T4: Refactor SearchInput Component
**Status:** MUST (unblocks SearchPopover composition)  
**Scope:** Modify `packages/ui/src/components/filters/SearchInput.tsx` (current lines 1-150+)  
**Acceptance Criteria:**
- Rename component to `SearchInputCore` (internal use only inside SearchPopover)
- Remove outer flex wrapper (`flex: 1 1 520px`, `minWidth: 360`, `maxWidth: 720`)
- Input element styling remains, but now rendered at full width inside popover container (popover controls width via CSS)
- Remove top-level focus/blur outline logic (SearchPopover or parent input element handles focus)
- "/" shortcut logic: migrate to FilterBar or SearchPopover parent; when "/" is pressed, parent calls `setIsSearchPopoverOpen(true)` and focuses the input
- Enter/Shift+Enter navigation logic remains (dispatches `ahp-search-nav` custom event)
- onClear callback remains unchanged

**Export Strategy:**
- Export both `SearchInputCore` (for SearchPopover internal use) and keep `SearchInput` as a re-export or deprecate
- Update FilterBar import: `import { SearchInputCore } from "./SearchInput.js"` or create new separate file
