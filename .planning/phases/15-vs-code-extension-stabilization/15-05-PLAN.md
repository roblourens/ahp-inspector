  <what-built>
The extension now hosts a singleton LogServer (Hono on 127.0.0.1:{ephemeral-port}) and the webview talks to it via WebviewOptions.portMapping. The bridge is gone. CSP includes the loopback origin and the UI bundle reads window.__AHP_API_BASE__ to prefix every fetch/EventSource URL.

This UAT validates the entire pivot in real VS Code (not unit tests):
- Local development flow
- Remote development flow (Codespaces or ssh-remote)
- No orphan processes
  </what-built>
  <action>
Execute the 8 verification scenarios below in real VS Code, capture a screenshot for each (or text output for Scenario 8), and write the UAT report.

**Pre-flight:**
```bash
pnpm install
pnpm -F @ahp-inspector/ui build
pnpm -F @ahp-inspector/extension build
mkdir -p screenshots/phase15
```

Then open this workspace in VS Code, press F5 to launch the Extension Development Host (or install the packaged VSIX).
  </action>
  <how-to-verify>
**Scenario 1 — Open a log (local):**
1. With VS Code focused on a `.jsonl` AHP file (use `test/fixtures/long-realistic-ahp.jsonl`), run command `AHP Inspector: Open` (or whatever the command title is).
2. Confirm panel opens, row list populates, no error overlay.
3. Open webview devtools (F1 → "Developer: Open Webview Developer Tools"), check the Network tab. Confirm /api/log/meta and /api/log/stream both return 200 (stream stays open).
4. Save screenshot → `screenshots/phase15/01-local-open.png`.

**Scenario 2 — Click a row, inspect state:**
1. Click a row that has notification/action content.
2. Confirm the state inspector pane on the right shows the parsed event detail.
3. Save → `screenshots/phase15/02-row-state.png`.

**Scenario 3 — Search:**
1. Type a query in the search box that matches some events.
2. Confirm the row list filters or highlights matches.
3. Devtools Network tab: confirm /api/log/search returned 200.
4. Save → `screenshots/phase15/03-search.png`.

**Scenario 4 — Switch active log:**
1. Open a SECOND `.jsonl` file in another editor tab (`test/fixtures/phase4.1-real-shapes.safe.jsonl` for example).
2. Re-run `AHP Inspector: Open` while focused on that second file.
3. Confirm the panel updates to show the second log's content (the row list visibly changes).
4. Save → `screenshots/phase15/04-log-switch.png`.

**Scenario 5 — Reconnect indicator:**
1. While the panel is open, kill the extension host (`Developer: Reload Window` is a softer alternative; or use Activity Monitor / `pkill -f extensionHost`).
2. Confirm the UI shows a reconnecting/disconnected state (the SSE stream drop is detected).
3. Save → `screenshots/phase15/05-reconnect.png`.

**Scenario 6 — No /api/ failures in devtools:**
1. Reload the extension dev host. Open a log fresh.
2. Open webview devtools Console + Network tabs.
3. Filter Network for `localhost`. Confirm no red rows (no failed /api/* requests).
4. Filter Console for "error". Confirm nothing related to fetch/CSP/EventSource.
5. Save → `screenshots/phase15/06-no-errors.png` (the devtools window).

**Scenario 7 — Remote dev sanity (Codespaces OR `code --remote ssh-remote+host`):**
1. Either: open this workspace in a Codespace, OR run `code --remote ssh-remote+<your-host> .` from a remote that has a JSONL log on it.
2. Run the same `AHP Inspector: Open` command in the remote window.
3. Confirm the panel works exactly as in Scenario 1 (this proves portMapping tunnels the loopback through VS Code's remote port forwarding).
4. Save → `screenshots/phase15/07-remote-dev.png`.

If remote dev is genuinely unavailable (no Codespace credit, no ssh target handy), document this in the UAT report as "deferred — remote sanity will be tested before v1.2 ship" rather than skipping silently.

**Scenario 8 — No orphan processes:**
```bash
# Before opening the panel:
lsof -nP -iTCP -sTCP:LISTEN | grep node | wc -l  # baseline
# Open panel, confirm a new node listener exists on 127.0.0.1:{ephemeral}.
lsof -nP -iTCP -sTCP:LISTEN | grep node
# Reload window (this triggers deactivate).
# Then check again:
lsof -nP -iTCP -sTCP:LISTEN | grep node
```
Confirm the new listener is gone after window reload (deactivate fired close).
Save the terminal output → `screenshots/phase15/08-no-orphans.txt` (text file is fine).
