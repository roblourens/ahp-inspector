Existing pattern from `test/boundary.test.ts`:
- Uses `node:fs` (`readdirSync`, `readFileSync`, `statSync`) and `node:path` — these are allowed in `test/` (boundary file is itself a test, not product code).
- `walk(dir)` returns all `.ts` / `.tsx` files (currently excluding `.test.ts` / `.test.tsx`).
- `IMPORT_RE = /(?:^|\b)(?:import\s[^"';]*?from\s*|export\s[^"';]*?from\s*)["']([^"']+)["']/g;`
- Uses `describe(...)` + per-file `it(...)`.

KEY DISTINCTION needed for the new rule: type-only imports MUST be allowed. The existing `IMPORT_RE` captures both `import { x }` and `import type { x }` — but matching against the SOURCE specifier alone cannot tell them apart. Use a SEPARATE regex that explicitly excludes `import type`:

```typescript
const RUNTIME_IMPORT_RE = /^\s*import\s+(?!type\b)[^"';]*?from\s*["']([^"']+)["']/gm;
```

This skips lines starting with `import type ...`. Lines like `import { type Foo } from "x"` are still RUNTIME imports (only the whole-line `import type` form is a pure type-only import) — that matches the standard TypeScript convention.

Forbidden specifier pattern:
```typescript
const FORBIDDEN_TRANSPORT = /transport\/(http|sse|search|state|sessions)-client(\.js)?$/;
```
