<objective>
Refactor the detail subsystem (DetailPanel + StateInspectorPanel) to route all transport calls through the injected `AhpViewerClient` instead of importing concrete `http-client` / `state-client` functions at runtime. Migrate their tests to configure the fake client via `<AhpViewerClientProvider>` instead of `vi.mock(...)`.

Purpose: This is the primary bug surface — row-click currently 403s inside the VS Code webview because `DetailPanel.tsx` calls `fetchEvent` from `transport/http-client.js` directly, which is the standalone HTTP path. Routing through the injected client makes it use `webview-client.postMessage` when running in the extension.

Output: 2 components refactored, 2 test files migrated, both still green.
</objective>
