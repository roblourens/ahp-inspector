# Plan 32-01 — Security hardening

**Phase:** 32 — Code review remediation
**Wave:** 1
**Requirement:** CR-SEC

## Objective

Close the cross-site / local-file-read exposure created by reflecting an
arbitrary `Origin` back as `access-control-allow-origin`. A malicious web page
can already reach `http://127.0.0.1:<port>` (the host-guard only checks the
`Host` header, which is loopback for a direct request); reflecting its `Origin`
lets it *read* responses and drive state-changing routes. Replace reflection
with a strict allow-list, gate mutating `/api/*` routes on origin, enforce the
upload size limit before buffering, and cap concurrent SSE streams.

## Tasks

1. **Origin allow-list helper** (`packages/server/src/origin.ts`, new):
   `isAllowedOrigin(origin: string | undefined): boolean`. Allowed:
   - missing origin (same-origin / non-browser),
   - `http(s)://127.0.0.1[:port]` and `http(s)://localhost[:port]`,
   - `vscode-webview://*` (VS Code webview panels),
   - `null` literal (sandboxed webview).
   Everything else is disallowed. Unit-tested in `origin.test.ts`.

2. **CORS lock-down** (`cors.ts`): only set `access-control-allow-origin` (and
   the OPTIONS preflight echo) when `isAllowedOrigin(origin)` is true; otherwise
   omit the header so the browser blocks the cross-origin read. Keep `vary:
   Origin`. Never set credentials.

3. **Origin gate** (`cors.ts` or a small `originGuardMiddleware`): if a request
   carries an `Origin` header that is **not** allowed, reject state-changing
   methods (`POST`, `PUT`, `PATCH`, `DELETE`) with `403`. GET stays open
   (same-origin GET has no `Origin`; cross-origin reads are already blocked by
   step 2).

4. **Upload size check before buffering** (`upload-routes.ts`): reject when the
   declared `Content-Length` exceeds the limit, and enforce the cap while
   reading the stream so an oversized/though-chunked body cannot buffer fully
   first. Return `413` with a code-only body.

5. **SSE connection cap** (`sse-routes.ts`): track active `/api/log/stream`
   connections; when at the cap (e.g. `MAX_SSE_CONNECTIONS = 8`) return `503`
   with `{code:"too-many-streams"}`; decrement on stream close/abort.

## Verification

- `cors.test.ts` updated: disallowed origin (e.g. `https://evil.example`) gets
  **no** ACAO header and a `403` on POST; allowed loopback/webview origins still
  work; OPTIONS preflight only echoes allowed origins.
- New upload oversize test returns `413` without buffering the whole body.
- New SSE cap test returns `503` past the limit and recovers after a close.
- `pnpm vitest run` green (no regression of the 1368 baseline); loopback UI
  still loads and an upload still succeeds.
