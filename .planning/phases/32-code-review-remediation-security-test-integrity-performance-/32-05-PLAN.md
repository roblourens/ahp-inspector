# Plan 32-05 — CSS z-index scale

**Phase:** 32 — Code review remediation
**Wave:** 2
**Requirement:** CR-CSS

## Objective

There is no z-index scale: magic values collide (e.g. two layers at `1200`) and
the CRT overlays sit at `1300`, above interactive controls. Introduce one token
scale and re-layer the surfaces so controls, drawer, dialogs, and decorative
CRT overlays stack predictably.

## Tasks

1. **Define a z-index token scale** in the global token sheet, e.g.
   `--z-base`, `--z-sticky`, `--z-controls`, `--z-drawer-backdrop`, `--z-drawer`,
   `--z-dialog`, `--z-crt-overlay`, `--z-toast`, with the decorative CRT overlay
   **below** interactive controls/dialogs.

2. **Replace magic numbers**: swap hard-coded `z-index` values across components
   (timeline sticky header, filter popovers, detail drawer, Switch-log dialog,
   CRT surfaces) for the tokens.

3. **Verify stacking**: ensure CRT decoration never occludes clickable controls
   and dialogs/drawers sit above the sticky header.

## Verification

- `grep -rn "z-index" packages/ui/src` shows tokenized values only (no stray
  magic numbers in components).
- `pnpm vitest run` green (including any z-index/style guard tests).
- Loopback UI (and Hacker theme) spot-check: pickers, dialog, and drawer are
  clickable and correctly layered above CRT overlays.
