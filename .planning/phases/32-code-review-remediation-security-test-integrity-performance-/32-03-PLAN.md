# Plan 32-03 — Architecture boundary (server → HostAdapter)

**Phase:** 32 — Code review remediation
**Wave:** 1
**Requirement:** CR-ARCH

## Objective

`packages/server/src/session-routes.ts` imports `discoverVsCodeLogs` directly
from `@ahp-inspector/host-node`, hard-wiring the portable server to a specific
Node host implementation and bypassing the `HostAdapter` seam the architecture
relies on (the same seam that lets the future VS Code extension swap hosts).
Route discovery through the injected adapter instead.

## Tasks

1. **Thread discovery through the adapter**: have `registerSessionRoutes`
   obtain discovery from the `LogSessionManager` / injected `HostAdapter`
   (e.g. `sessions.discover()` or a `host.discoverLogs()` passed in) rather than
   importing `host-node`.

2. **Remove the direct dependency**: delete the
   `import { discoverVsCodeLogs } from "@ahp-inspector/host-node"` line; confirm
   `packages/server/package.json` no longer needs `host-node` as a runtime dep
   (move to the composition root — cli/extension — if it lingers).

3. **Wire the adapter at the composition root**: ensure the CLI/server startup
   passes the concrete `host-node` discovery into the session manager so runtime
   behavior is unchanged.

## Verification

- `grep -rn "@ahp-inspector/host-node" packages/server/src` returns nothing.
- `/api/sessions/discover` still returns real candidates when run from the CLI.
- `pnpm vitest run` green; `pnpm -r build` (or the server build) succeeds with
  the dependency removed/relocated.
