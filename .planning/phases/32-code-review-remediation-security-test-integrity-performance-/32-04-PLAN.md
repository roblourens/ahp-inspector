# Plan 32-04 — UI performance

**Phase:** 32 — Code review remediation
**Wave:** 2
**Requirement:** CR-PERF

## Objective

The timeline recomputes derived row data far more than necessary:
`useFilteredRows` runs ~3× and `useGroupedItems` ~2× per render, `EventRow`'s
`memo` is defeated by inline `onClick`/`style` props created fresh each render,
and the default `method:["ping"]` filter forces the slower filtered code path
even when the user has not filtered anything. Reduce redundant work without
changing visible behavior.

## Tasks

1. **Single derivation**: compute filtered rows and grouped items once per
   render (lift to one `useMemo` each, or a single selector) and pass results
   down; remove duplicate hook invocations.

2. **Stabilize `EventRow` props**: provide a stable row-click handler (e.g.
   `useCallback` keyed by index/id, or row-level handler indirection) and avoid
   constructing new inline `style` objects per render so `React.memo(EventRow)`
   actually short-circuits.

3. **Default-filter slow path**: keep `ping` hidden by default via a cheap
   predicate that does not flip the list into the general filtered path when the
   user has applied no real filter (preserve the existing default-hidden `ping`
   behavior and persistence).

## Verification

- `pnpm vitest run` green; existing filter/group/ping tests unchanged.
- Default-hidden `ping`, filter persistence, 100-row cap, and grouping behave
  identically (spot-check in the loopback UI).
- A render-count or memo assertion (where one exists) confirms `EventRow` no
  longer re-renders on unrelated state changes.
