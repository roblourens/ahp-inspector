# Phase 34 — UI Design Contract

> Visual and interaction contract for the find/navigation rework. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Locked decisions D-01..D-13 (see `34-CONTEXT.md`) are the authoritative acceptance surface. This contract makes them concrete and prescriptive without re-opening them.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — established custom CSS-token system (no `components.json`, no shadcn) |
| Preset | not applicable |
| Component library | none (hand-rolled components; `react-json-view-lite@2.5.0` for the Pretty JSON tree) |
| Icon library | `lucide-react@1.14.0` (`ChevronUp`, `ChevronDown`, `X`) |
| Font | `--font-sans` = Inter Variable; `--font-mono` = JetBrains Mono Variable |

**Token source of truth:** `packages/ui/src/styles/tokens.css` (dark / light / hacker). **Z-order source of truth:** `packages/ui/src/styles/tokens.css` `--z-*` mirrored by `packages/ui/src/styles/zLayers.ts` (`Z`), parity-guarded by `zLayers.test.ts`. **Do not introduce new tokens, new z-layers, or per-theme component branches** — reuse existing tokens only.

## Spacing Scale

Use the existing `--space-*` ladder only. All values are multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-1` | 4px | Icon gaps, nav-button cluster gap, popover `marginTop` |
| `--space-2` | 8px | Find popover padding, internal stack gap, drawer close inset |
| `--space-3` | 12px | Popover right inset from filter bar edge (`right: 12`) |
| `--space-4` | 16px | Detail content block spacing |
| `--space-5` | 24px | Section padding |
| `--space-6` | 32px | Layout gaps |
| `--space-8` | 48px | Major section breaks |

Exceptions (pre-existing, do not change): `--row-height: 21px`, `--filter-bar-height: 40px`, `--filter-chips-height: 32px`, drawer close target `32px`, nav-button icon `16px`. The 32px close target and 16px icon sit inside a 32px hit area — keep the find prev/next buttons at the same **minimum 32×32px hit target** even though the glyph is 16px (touch/click reliability for D-11).

## Typography

Use existing type tokens only; no new sizes or weights.

| Role | Token | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Body / detail text | `--text-body-size` | 14px | `--weight-regular` (400) | 1.5 (existing detail default) |
| UI control / input | `--text-ui-size` | 13px | 400 | normal |
| Status / counter (muted) | `--text-ui-muted-size` | 12px | 400 | normal |
| Timeline row | `--text-row-size` / `--text-row-line` | 13px / 20px | 400 | 20px |
| Heading | `--text-heading-size` | 16px | `--weight-semibold` (600) | 1.2 |

**Weights:** exactly two — 400 regular, 600 semibold. Highlighted (`<mark>`) text keeps the **same weight** as its surrounding text; emphasis comes from background color, not from bolding (D-08).

## Color

60 / 30 / 10 split maps onto the existing token roles. Values shown for dark theme; light/hacker resolve from the same token names automatically.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` (#0e1116) | App background, timeline canvas, drawer/rail base |
| Secondary (30%) | `--color-surface`, `--color-surface-raised`, `--color-border*` | Find popover surface (`--color-surface-raised`), detail rail/drawer (`--color-surface`), borders |
| Accent (10%) | `--color-accent` (#7aa2f7) | Reserved list below only |
| Destructive | `--color-destructive` (#f7768e) | Search-error status text only |

**Accent (`--color-accent`) is reserved for, and ONLY for:**
- The focus ring (`--focus-ring`) on the find input and prev/next buttons (2px outline).
- Selected-row background (`--row-selected-bg`, accent-mix) and hover (`--row-hover-bg`).
- Active detail tab indicator (existing `DetailTabs` treatment).

**Accent is NOT used for** the search-match highlight. Query highlighting uses the dedicated, already-tokenized pair:
- `--color-search-match-bg` / `--color-search-match-fg` (dark `#3a3520`/`#e6e9ef`, light `#fff0a8`/`#18202c`, hacker `#254512`/`#d6ffe2`).

This keeps the row-precedence contract from Phase 14 intact: `selected` (accent bg) > `pair-highlight` > `search-match` (the `<mark>` glyph/bg), so a selected match still reads as selected, not as accent-colored highlight noise.

**Status-text color rule:** muted (`--color-text-muted`) for normal/searching/result counts; `--color-destructive` for the error state. (Note: current code references a nonexistent `--color-danger` for the error branch — correct it to `--color-destructive`.)

## Copywriting Contract

Find navigation is **event-oriented** (D-06/D-07): one result = one request/response/notification event containing ≥1 match. Copy must never imply a count of text occurrences.

| Element | Copy |
|---------|------|
| Find input placeholder (existing, keep) | `all JSON payloads, methods, ids, sessions...` |
| Find input aria-label (existing, keep) | `Search all events` |
| Counter — active result | `{n} of {m} results` (e.g. `3 of 24 results`); append `+` when `searchTruncated` → `3 of 24 results+` |
| Counter — before navigating | `{m} results` (e.g. `24 results`); append `+` when truncated |
| Counter — singular | `1 result` / `1 of 1 result` (singularize "result", drop the old "match/matches" wording) |
| Searching | `Searching…` |
| No matches (query present, 0 results) | `No matching events` |
| Error | `Search failed: {searchError}` (rendered in `--color-destructive`); when `{searchError}` is empty, use `Search failed — check the server connection and try again` |
| Empty (no query typed) | no status text rendered (status row hidden) — unchanged |

**Primary action of this phase:** there is no new CTA button; the primary interaction is keyboard navigation through results. The find prev/next buttons keep icon-only affordances with text alternatives via aria-label.

**Accessible announcements (D-07, the agent's-discretion → specified):**
- The counter region is a polite live region: `role="status"` (or `aria-live="polite"`) + `aria-atomic="true"` on the status `<span>`, so each navigation announces e.g. "3 of 24 results".
- Prev/next buttons: `aria-label="Previous result"` / `aria-label="Next result"` (reword from current "…search match" to match results language).
- The find region keeps `role="region"` `aria-label="Find"` (reword from "Search popover" to a user-facing term; container `data-testid="search-popover"` stays for tests).
- Disabled prev/next when `!hasSearchMatches` keep `disabled` + non-interactive cursor; do not rely on color alone.

**No destructive actions** are introduced in this phase. Escape is non-destructive: it closes the find widget but **preserves** the query and results (D-13). No confirmation dialogs.

## Interaction Contract — Find Widget Placement & Z-Order (D-04, D-10)

| Property | Value |
|----------|-------|
| Anchor | Rendered inside `FilterBar`, `position: absolute; top: 100%; right: var(--space-3)`, `marginTop: 4px`. |
| Surface | `width: 344px`, `maxWidth: calc(100% - 24px)`, `background: --color-surface-raised`, `border: 1px solid --color-border-strong`, `borderRadius: 6px`, `boxShadow: --shadow-menu`, `padding: --space-2`. |
| Stacking | `zIndex: Z.popover` (1100). This sits **above the desktop detail rail**, which renders in `.app-main` at default/base stacking with only `--shadow-panel` (no elevated z) — so D-10 holds: the non-modal desktop rail can never cover the find widget. |
| Narrow drawer relationship (D-04) | The narrow-screen drawer renders at `Z.drawer` (2010) over `Z.drawerBackdrop` (2000) — **above** the find popover. This is intentional and correct: an explicit row click may open the drawer *over* the still-open find widget. Search-driven navigation must NOT open it (see below). |
| Responsive dimensions | Popover keeps 344px fixed width down to `calc(100% - 24px)`; on `<768px` the filter bar is horizontally scrollable (existing), popover still right-anchored. No new breakpoints. |

The find widget is **non-modal**: it never renders a backdrop, never traps focus, and never blocks the timeline behind it.

**Focal point:** within the find widget the search `<input>` is the primary focal point — it sits at the top of the stack, takes full surface width, and holds focus by default. The result counter and the prev/next nav buttons are visually subordinate: muted 12px text and 16px icon-only glyphs in a 32×32px hit area, never competing with the input for emphasis.

## Interaction Contract — Desktop Rail Sync vs Narrow Drawer Suppression (D-01..D-05)

Breakpoint: `DETAIL_DESKTOP_BREAKPOINT = 1400px` (`min-width: 1400px` → persistent **desktop rail**; below → **drawer**). Do not change this value.

| Scenario | Desktop rail (≥1400px) | Narrow drawer (<1400px) |
|----------|------------------------|-------------------------|
| Enter / Shift+Enter / prev / next / F3 (search-driven) | Rail **updates** to the matching event (D-01). Rail update **must not move focus** out of the find input/button (D-05). | Drawer **stays closed**; row is selected but not opened (D-02). |
| Explicit timeline-row click | Rail updates as today. | Drawer **may open** over the still-open find widget (D-04); existing close-button focus transfer applies only on this open. |
| Escape closes find after search navigation | Rail stays as-is; selection preserved (D-03). | Drawer **stays closed** (D-03); selection preserved. |

**Implementation contract (the agent's-discretion → specified):** introduce a single `selectionSource: "search" | "explicit"` discriminator alongside `selectedIdx` (no duplicate index). The drawer-open derivation in `AppShell` changes from `!isDetailDesktop && selectedIdx !== null` to additionally require `selectionSource === "explicit"`. The existing `drawerWasOpenRef` first-open focus latch is preserved and only fires for explicit opens.

## Interaction Contract — Focus Behavior (D-11, D-12, D-13)

| Trigger | Focus result |
|---------|--------------|
| Enter / Shift+Enter in find input | Selection advances ±1 event; **focus stays in the find input** (no blur on dispatch). D-11. |
| Click prev / next button | Selection advances; **focus stays on the clicked button** (do not return focus to input, do not blur). D-11. |
| Cmd/Ctrl+F while find is **closed** | Open find, focus input (existing). Suppresses browser-native find (`preventDefault`). |
| Cmd/Ctrl+F while find is **already open** | **Refocus the input and select its entire current query** (`input.select()`) for replace-typing. D-12. (Today `FilterBar` early-returns when open — change so the shortcut still refocuses+selects.) |
| Repeated Enter on narrow viewport | Must keep advancing — focus never leaves input because the drawer never opens for search selection (D-02 guards D-11). |
| Escape | Close find, **preserve** query + results, then **move focus to the current matching timeline row** (D-13). Not to the toolbar trigger, not to a previously focused control. Escape priority order (existing) is preserved: close find before clearing search/selection. |
| Desktop rail content update | Never calls `.focus()`; the rail is a passive render target (D-05). |

Focus rings everywhere use `--focus-ring` (= `--color-accent`) at 2px, matching the existing input/button treatment. Respect `:focus-visible` semantics already in use.

## Interaction Contract — Query Highlighting (D-08)

Single shared highlighter, extracted from `EventNameLabel.tsx` (`findMatchRanges` + `renderHighlightedSegment`) into a shared module and reused — **never reimplemented**.

| Surface | Highlight behavior |
|---------|--------------------|
| Matching timeline row | Existing `<mark>` highlight via `EventNameLabel` — keep. |
| Detail Summary view | Highlight literal query occurrences in rendered summary text. |
| Detail Pretty (JSON tree) | Highlight literal query occurrences in keys/values via React text children. |
| Detail Raw view | Highlight literal query occurrences in the `<pre>` text. |

**Highlight rules (security-critical):**
- Matching is **literal, case-insensitive**, via `String.indexOf`/`includes` — **never** a `RegExp` compiled from the query (ReDoS mitigation T-03-01-01; literal only).
- Minimum query length 2 (existing `findMatchRanges` behavior) — shorter queries highlight nothing.
- Non-overlapping ranges; render as `<mark style="background:var(--color-search-match-bg); color:var(--color-search-match-fg)">`.
- **NO `dangerouslySetInnerHTML`** anywhere. Arbitrary JSON payload text is highlighted exclusively through escaped React children (`RawJsonView`/`PrettyJsonView` carry an explicit auto-escape guarantee).
- `<mark>` keeps surrounding font, size, and weight; only background/foreground change.

## Interaction Contract — Reveal First Hidden Match (D-09)

If the selected event's first relevant match is hidden, reveal it **without changing event-level navigation semantics** (still one advance per event):

| Hidden by | Reveal action |
|-----------|---------------|
| Wrong detail tab (match only on Pretty vs Raw) | Select the tab that can show the match. Default precedence: prefer the currently active tab if it contains the match; otherwise switch to the tab that does. |
| Collapsed JSON branch (Pretty) | Auto-expand the path to the first match using `react-json-view-lite`'s `shouldExpandNode(level, value, field)` predicate (subtree-contains-query, case-insensitive, literal). Because expansion is uncontrolled, **remount via `key={selectedIdx + ":" + query}`** so a new selection/query re-seeds expansion. |
| Raw view | `<pre>` is fully expanded already — no branch expansion needed. |
| View genuinely cannot expose the match (e.g. match in a field elided behind the >256KB truncation banner) | Do nothing destructive: keep the row selected and highlighted, leave navigation semantics unchanged. No error, no forced expansion of everything. |

**Stability requirement (manual-verified):** reveal must reseed only on `selectedIdx`/`query` change — manual expand/collapse of unrelated branches must survive re-renders that don't change selection or query.

## Responsive, Accessibility & Motion Expectations

- **Themes:** dark, light, hacker must all resolve from the shared token names above with no per-theme component branches. The pinned find widget must remain legible and unobstructed in all three at desktop width (manual sign-off item).
- **Accessibility:** counter announced via polite live region; prev/next/input have text labels; disabled state not color-only; focus order remains logical (input → prev → next); Escape returns focus to a real, visible element (the matching row, which must be focusable/scrolled into view).
- **Contrast:** the `--color-search-match-bg` / `--color-search-match-fg` pairs are pre-tuned per theme — do not substitute accent or semantic colors that would fail contrast against highlighted text.
- **Reduced motion:** honor `prefers-reduced-motion: reduce`. Scroll-the-match-into-view must not introduce smooth-scroll animation under reduced motion (use instant/`auto` alignment); add no new transitions/animations to the find widget, tab switches, or branch expansion. Existing reduced-motion blocks in `global.css` already disable hacker-theme CRT animation — do not regress them.

## Constraints (hard limits for this phase)

- **No new dependencies.** Use react, zustand, react-json-view-lite, lucide-react already present.
- **No server / transport / protocol changes.** Search already returns event-indexed matches; consume them.
- **No `dangerouslySetInnerHTML`.**
- **No `RegExp` compiled from the user query** for highlighting or matching — literal substring only.
- **No new tokens or z-layers**; reuse `tokens.css` / `zLayers.ts` and keep `zLayers.test.ts` parity.
- **Do not turn search into a row filter** and do not add a search query language — non-matching rows stay visible (highlight + navigate only).
