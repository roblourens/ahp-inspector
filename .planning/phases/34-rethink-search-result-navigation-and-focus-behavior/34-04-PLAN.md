<objective>
Highlight the active query inside the selected event's detail content (D-08) and reveal the first hidden match (D-09), consuming the shared highlighter from Plan 01 and react-json-view-lite's existing expansion hook.

- Raw view + Summary: render with the shared `HighlightedText` (`<mark>` + theme tokens), fully controlled React text children.
- Pretty (JSON tree): auto-expand the path to the first match via a match-aware `shouldExpandNode`, with a `key`-based remount so a new selection/query reseeds expansion (RESEARCH Pattern 2 / Pitfall 2). Visibly highlight literal matches via the **CSS Custom Highlight API** — the XSS-safe, no-DOM-injection mechanism — because react-json-view-lite@2.5.0 exposes NO per-node render hook (`Props` = data/style/shouldExpandNode/clickToExpandNode/beforeExpandChange/compactTopLevel only). This honors "no dangerouslySetInnerHTML" and "literal, non-regex matching" while reusing `--color-search-match-bg/-fg`.

> DESIGN NOTE (divergence from 34-UI-SPEC §Query Highlighting): the UI-SPEC prescribes a literal `<mark>` element for the Pretty tree. That is infeasible for a third-party tree without swapping the renderer (forbidden) or `innerHTML` (forbidden). The CSS Custom Highlight API delivers the same literal, token-colored highlight intent safely. Raw + Summary still use `<mark>`. Record this in the SUMMARY for UI-checker awareness.

Purpose: Implements D-08 (detail highlight) and D-09 (reveal first hidden match).
Output: highlighted Raw/Summary/Pretty + reveal logic, with tests.
</objective>

```tsx
function subtreeContainsQuery(value: unknown, q: string): boolean {
  if (q.length < 2) return false;
  let s: string;
  try { s = JSON.stringify(value); } catch { return false; }
  if (s.length > 512 * 1024) return false; // bound the scan
  return s.toLowerCase().includes(q.toLowerCase());  // literal, no RegExp
}
```
2. Replace `shouldExpandNode={(level) => level < 5}` with a match-aware predicate that, when a query is present, expands the path to matches and otherwise keeps the existing default:
```tsx
shouldExpandNode={(level, value) =>
  query.trim().length >= 2 ? (level < 1 || subtreeContainsQuery(value, query)) : level < 5
}
```
3. Add a `useRef<HTMLDivElement>` on the `ahp-json-view` container and a `useEffect` (deps: `[data, query]`) that registers a CSS Custom Highlight over literal query ranges in the rendered text nodes, feature-detected:
```tsx
useEffect(() => {
  const root = containerRef.current;
  const q = query.trim();
  if (!root || q.length < 2) { (globalThis as any).CSS?.highlights?.delete("ahp-search-match"); return; }
  if (typeof (globalThis as any).Highlight === "undefined" || !(globalThis as any).CSS?.highlights) return;
  const ranges: Range[] = [];
  const walker = document.createTreeWalker(root, NodeFilter.SHOW_TEXT);
  const lowerQ = q.toLowerCase();
  for (let n = walker.nextNode(); n; n = walker.nextNode()) {
    const text = n.nodeValue ?? "";
    const lower = text.toLowerCase();
    let i = lower.indexOf(lowerQ);
    while (i !== -1) {
      const r = document.createRange();
      r.setStart(n, i); r.setEnd(n, i + q.length);
      ranges.push(r);
      i = lower.indexOf(lowerQ, i + q.length);
    }
  }
  (globalThis as any).CSS.highlights.set("ahp-search-match", new (globalThis as any).Highlight(...ranges));
  return () => { (globalThis as any).CSS?.highlights?.delete("ahp-search-match"); };
}, [data, query]);
```
Keep this literal (no RegExp). Attach `ref={containerRef}` to the existing container div.

