# Phase 04.1 — UI Design Contract

> Visual and interaction contract for the inserted timeline row information polish phase.

---

## Phase Boundary

This phase improves the information architecture of timeline rows before Phase 5 theme and responsive polish. It covers column order, event-specific row summaries, request/response pairing affordances, error annotation after removing the status column, session/turn extraction display, Pretty JSON defaults, action-marker clarity, and privacy-safe real-log validation.

Out of scope: Phase 5 theme picker work, hacker/CRT effects, responsive detail drawer, new component libraries, shadcn setup, third-party registries, telemetry, remote log upload, export, bookmarks, annotations, and multi-log comparison.

---

## Design System

| Property | Contract |
|----------|----------|
| Component system | Existing custom React components only |
| Styling | Existing CSS custom properties in `packages/ui/src/styles/tokens.css` |
| Icons | Existing `lucide-react` only |
| Fonts | Existing `Inter Variable` for UI and `JetBrains Mono Variable` for timeline IDs/methods/summaries/JSON |
| Registry | None; no shadcn initialization and no third-party UI registry blocks |
| Network | No outbound network dependency for viewing or validating logs |

Implementation may add semantic class names and token references, but component files must not introduce raw color literals.

|------|------|--------|-------------|------|

## Color Contract

Use theme tokens only. The existing 60/30/10 visual balance maps to:

| Role | Token | Usage |
|------|-------|-------|
| Dominant | `--color-bg` | timeline scroll body and app background |
| Secondary | `--color-surface`, `--color-surface-raised` | header rows, selected row fill, panels |
| Accent | `--color-accent` | selected row rail, keyboard focus, active detail tab |
| Destructive | `--color-destructive` | error response, parse error, auth failure |
| Warning | `--color-warning` | timeout/unmatched/orphan annotations |
| Info | `--color-info` | correlated-pair secondary highlight |

Accent must not be used for every interactive element. Error/warning state cannot rely on color alone; every such row needs visible text or an accessible label.

Primary focal point: the selected timeline row is the main visual anchor. Within each row, users should scan `ID -> Event -> Summary` first; pair highlights and error badges are secondary emphasis, and latency/session/turn remain supporting metadata.

## Timeline Column Contract

The standalone `Status` column is removed. `ID` becomes the first visible data column. The row state rail remains before it and has no visible text.

| Order | Key | Header | ARIA Label | Width | Display Contract |
|------:|-----|--------|------------|-------|------------------|
| 0 | rail | empty | Row state | 4px | state/selection/error rail only |
| 1 | id | `ID` | Request or event ID | 96px | JSON-RPC id; `—` only when source lacks id |
| 2 | time | `Time` | Time | 96px | UTC `HH:mm:ss.SSS`, mono tabular |
| 3 | direction | `Dir` | Direction | 16px | `→`, `←`, or `·` for explicit unknown |
| 4 | kind | `Kind` | Event kind | 44px | existing `REQ`, `RES`, `NTF`, `ACT`, `BAD`, `LOG` tag |
| 5 | event | `Event` | Event method or type | 220px | method/action/notification type; no internal taxonomy |
| 6 | session | `Session` | Session | 132px | safe short session value or `—` |
| 7 | turn | `Turn` | Turn | 72px | safe short turn value or `—` |
| 8 | latency | `Latency` | Latency | 72px | existing latency text/bar retained |
| 9 | summary | `Summary` | Parsed event summary | minmax(240px, 1fr) | event-specific summary replacing generic payload preview |

Required grid template:

```ts
export const TIMELINE_GRID_COLUMNS =
  "4px 96px 96px 16px 44px 220px 132px 72px 72px minmax(240px, 1fr)";
```

Executor may tune fixed widths by ±16px only if UAT proves truncation, but must preserve order and intent.

## Row Summary Contract

The visible label is `Summary`, not `Payload`. Implementation may either rename `payloadPreview` to `summary` or keep the internal field for compatibility while rendering/testing/copying it as a summary.

Preferred component/test surface:

| Surface | Contract |
|---------|----------|
| Component | `SummaryCell` preferred; repurposed `PayloadPreview` acceptable only if user-facing naming changes |
| Test id | `row-summary` |
| Header | `Summary` |
| Font | mono, 13px |
| Length | cap generated summary at 160 chars before render |
| Rendering | React text rendering only; never inject HTML |
| Layout | single-line ellipsis |

Use the first matching summary rule:

| Event Shape | Summary Pattern |
|-------------|-----------------|
| Parse error | `parse error line <line>: <reason>` |
| JSON-RPC error response | `error <code>: <message>` |
| Success response with correlated request method | `<requestMethod> result <result summary>` |
| `resourceList` request/method | `resourceList uri=<uri>` |
| `delta` action/notification | `delta "<content snippet>"` |
| Tool call action | `tool call <toolName> <arg summary>` |
| Tool result action | `tool result <toolName or toolCallId> <result summary>` |
| Text action | `text "<content snippet>"` |
| Status/progress action | `status <state or message>` |
| Protocol notification | `notification <type> <summary>` |
| Client/server notification | `<method> <summary>` |
| Generic request | `<method> <param summary>` |
| Generic response | `result <result summary>` or `empty result` |
| Log/internal | `log <message>` |
| Unknown action with type | `action <actionType>` |
| Unknown action without type | `action details unavailable` |
| Unknown method shape | `<method> details unavailable` |

Extraction priority:

| Category | Fields |
|----------|--------|
| URI/resource | `params.uri`, `params.resource.uri`, `params.resource`, `params.resources[0].uri`, safe basename of `params.path` |
| Text/delta | `params.delta`, `params.content`, `params.text`, `params.message`, `params.action.delta`, `params.action.content`, `result.content`, `result.text` |
| Tool name | `params.toolName`, `params.name`, `params.tool.name`, `params.action.toolName`, `params.action.name` |
| Tool call id | canonical `event.toolCallId`, `params.toolCallId`, `params.toolCall.id`, `params.action.toolCallId` |
| Error | `raw.error.code`, `raw.error.message`, `raw.error.data.message` |

Useful args: include at most 3 primitive key/value pairs as `key=value`, redact path/token-like values, collapse objects to `{…}`, collapse arrays to `[N]`.

Snippet formatting:

| Input | Output |
|-------|--------|
| empty or whitespace string | `empty` |
| string <= 80 chars | trimmed string |
| string > 80 chars | first 79 chars + `…` |
| object | up to 3 primitive key/value pairs |
| array | `[N items]` |
| null/undefined | `empty` |

## Error Annotation Without Status Column

Rows are error-annotated when `row.status === "error"`, `row.kind === "parse-error"`, `row.isAuthFailure === true`, or a response has `raw.error`.

| Condition | Required Row Treatment |
|-----------|------------------------|
| Error response | destructive rail plus inline badge `ERR` near the Event label |
| Parse error | existing `BAD · line <n> · <reason>` parse-error row with destructive styling |
| Auth failure | existing ShieldAlert affordance plus `AUTH` badge or destructive accessible label |
| Unmatched request | warning rail or badge `TIMEOUT`; not a status column |
| Orphan response/request | warning rail or badge `ORPHAN`; not a status column |
| Pending request | no loud badge unless selected/detail; latency remains `—` |

Forbidden main-timeline status tokens: `2xx`, `n/a`, standalone `—` status values, and a `Status` header.

## Request/Response Highlight Interaction

| User Action | Required Behavior |
|-------------|-------------------|
| Click request row | select request and highlight correlated response if visible |
| Keyboard Enter/Space on request row | same as click |
| Arrow to request row | existing selection behavior; pair highlight updates immediately |
| Click response row | select response and highlight correlated request if visible |
| Select unmatched request | no pair highlight; row may show warning annotation |
| Escape/clear selection | remove selected and pair highlights |

Pair highlight must use stable event `idx`, not virtual item index. It must survive virtualization: when the paired row scrolls into view, it renders highlighted. Filtering/searching must not corrupt pair state.

If the selected row has a known pair hidden by current filters, do not insert a fake row. Add title/accessible copy to the selected row:

- `Correlated response is hidden by current filters`
- `Correlated request is hidden by current filters`

Required deterministic attributes:

| Attribute | Value |
|-----------|-------|
| `aria-selected` | `true` only for selected row |
| `data-selected` | `"true"` on selected row |
| `data-pair-highlight` | `"request"` or `"response"` on highlighted counterpart |
| `data-pair-hidden` | `"request"` or `"response"` on selected row when pair exists but is filtered out |

Pair highlight cannot create a second selected row.

## Session and Turn Display

Session and turn columns must show extracted values when source JSONL contains them.

| Source State | Session Cell | Turn Cell | Tooltip |
|--------------|--------------|-----------|---------|
| Value extracted | safe shortened session | safe shortened turn | full value only if privacy-safe |
| Source lacks value | `—` | `—` | `No session in source event` / `No turn in source event` |
| Raw source has value but row is empty | bug; do not ship | bug; do not ship | test must fail |
| Sensitive path/URI value | safe shortened label | safe shortened label | no absolute private path |

Required extraction coverage:

- `params.session`
- `params.session.uri`
- `params.sessionId`
- `params.turnId`
- `params.turn.id`
- `params.action.session`
- `params.action.sessionId`
- `params.action.turnId`
- `params.action.turn.id`
- `params.notification.session`
- `params.notification.sessionId`
- `params.notification.turnId`
- `params.notification.turn.id`

Shortening rules:

| Field | Display |
|-------|---------|
| UUID | first segment or last 8 chars, consistent with existing shortener |
| URI/path-like value | basename or last meaningful segment only |
| string <= 18 chars | full string |
| string > 18 chars | first 17 chars + `…` |
| turn id | last 6 chars unless shorter |

## Detail Pretty JSON Contract

Pretty JSON must default to expanded.

| State | Contract |
|-------|----------|
| New row selected | Detail panel opens on `Pretty` tab |
| Pretty initial render | nested AHP fields are immediately visible |
| User switches Raw | raw remains available |
| User returns Pretty | Pretty renders expanded by default for selected event |
| Huge payload over cap | existing truncation banner remains |

Minimum expansion contract:

```ts
shouldExpandNode={(level: number) => level < 5}
```

If performance regresses on large safe fixtures, executor may use a smarter rule that expands all nodes through level 4 and known AHP keys through level 6 while preserving the existing payload cap.

## Action Marker Decision

The existing marker that exposes action-family internals must be removed from timeline rows in Phase 04.1.

Action clarity moves into:

1. `Kind` tag (`ACT`).
2. `Event` label (`text`, `toolCall`, `toolResult`, `status`, or actual action type).
3. `Summary` text (`tool call <name> ...`, `delta "..."`, etc.).
4. Optional useful inline badge only for visible categories: `TOOL`, `TEXT`, `STATUS`.

Forbidden user-visible copy:

- `Action row family`
- `family unknown`
- `unknown family`
- `action row family unknown`

Unknown action fallback:

| Surface | Copy |
|---------|------|
| Event cell | `action` |
| Summary cell | `action details unavailable` |
| Tooltip | `Action details unavailable` |
| Marker/dot/badge | none |

## Accessibility and Keyboard Behavior

- Retain `role="grid"`, `role="row"`, and `role="gridcell"` semantics.
- Retain roving focus: selected row `tabIndex=0`; non-selected rows `tabIndex=-1`.
- Enter and Space on a focused row select it.
- Existing Up/Down/PageUp/PageDown/Home/End/Escape behavior must not regress.
- Pair highlight must not create a second selected row.
- Selected-row accessible label must include ID or `no id`, time, direction, kind, event label, error/warning annotation if present, and pair state if present.
- Focus uses existing `:focus-visible` token outline.
- This phase adds no motion; respect `prefers-reduced-motion`.
- Search highlighting must continue using escaped React text, never HTML injection.

## Privacy and Real-Log Fixture Validation

The real file `~/ahp-2026-05-08T03-02-25-575Z-ssh-macbook-air.jsonl` is validation input only until reviewed and scrubbed.

Before copying any data into the repository, remove or replace:

- tokens, API keys, authorization headers, cookies, secrets;
- private prompts, model output, chat content, and tool output content;
- absolute local paths such as `/Users/...`, `/home/...`, and `C:\...`;
- usernames, hostnames, machine names, SSH targets, email addresses;
- private repository names/URLs;
- raw file contents not needed for row UI validation.

Committed fixture contract:

| Property | Requirement |
|----------|-------------|
| Location | `test/fixtures/` or phase-specific safe fixture path chosen by planner |
| Format | JSONL |
| Size | minimal slice sufficient for Phase 04.1 |
| Required rows | request/response pair, error response, resourceList, delta, tool call, tool result, unknown action fallback, notification, populated session/turn, absent session/turn, parse error if safe |
| Forbidden content | secrets, prompts/output, absolute paths, hostnames/usernames, private URIs |
| Evidence | summary documents scrub commands/checks and fixture rationale |

Before UAT screenshots are approved, inspect rendered browser text for `/Users/`, `/home/`, `C:\`, `Authorization`, `Bearer`, `token`, and source-machine private hostname/user strings.
