# Phase 04.1: Timeline Row Information Polish and Real-Log Validation - Research

**Researched:** 2026-05-08  
**Domain:** AHP JSONL normalization, core row projection, virtualized React timeline UI, privacy-safe real-log fixture validation  
**Confidence:** High for codebase current state and implementation seams; medium for final fixture content because any real-derived fixture still needs privacy review.

## Summary

Phase 04.1 is a projection-and-rendering polish phase, not a dependency or architecture rewrite. Row data flows from `packages/parser` normalization, through `packages/core/src/row-projection.ts`, through `packages/server/src/app-state.ts` SSE snapshots/patches, into the Zustand store, and finally into `TimelineList`/`EventRow`.

The two highest-risk seams are:

1. **Pair highlighting:** request/response pair information is available through the correlator/detail path, but rows do not currently carry `pairIdx`. Add `pairIdx: number | null` to row projection and SSE patches so timeline highlighting is immediate and does not depend on an async detail fetch.
2. **Session/turn extraction:** current extraction covers only common top-level paths. The real-log structural audit found many useful values nested under action/notification envelopes, so extraction must expand before row UI validation.

Recommended execution order: fixture/scrub safety -> parser/core/server row contract -> timeline UI -> pair-highlight/detail expansion -> UAT/regression.

## Real-Log Structural Findings

The real JSONL file was useful for shape analysis, but it must not be committed raw. Research summarized only structural findings and did not preserve sensitive payload content.

Key findings:

- Current normalizer output over the real log showed almost no populated `sessionId`/`turnId` rows, while structural path counts found nested session/turn-like fields in many raw entries.
- Likely missing paths include `params.action.session`, `params.action.sessionId`, `params.action.turnId`, `params.action.turn.id`, `params.notification.session`, `params.notification.sessionId`, `params.notification.turnId`, and `params.notification.turn.id`.
- Useful summary-driving shapes observed include `resourceList`/resource-style requests, delta/content actions, tool call/result-like actions, protocol notifications, success responses, and error responses.
- A minimal synthetic or scrubbed fixture should mirror those shapes without copying private prompts, model output, paths, usernames, hostnames, tokens, or full raw content.

## Recommended Implementation Approach

### 1. Fixture and privacy guard first

Prefer a generated synthetic fixture that mirrors the real-log shapes. If using real-derived lines, create a minimal scrubbed slice only after manual privacy review.

Required fixture coverage:

- request/response pair;
- error response;
- `resourceList`;
- delta/content action;
- tool call and tool result;
- notification;
- unknown action fallback;
- populated session/turn;
- absent session/turn;
- parse error if safe.

Extend fixture scrub checks to reject obvious secrets and private content: `/Users/`, `/home/`, Windows drive paths, `Authorization`, `Bearer`, token/key/cookie words, GitHub PAT-like strings, OpenAI-key-like strings, JWT-like strings, emails, hostnames/usernames if known, and prompt/output sentinel content.

### 2. Fix parser extraction before UI

Extend the defensive extractor style in `extract.ts` to read nested action/notification paths for session/turn/tool fields. Add tests in `normalizer.test.ts` with synthetic raw events matching the real structural shapes.

Do not rely on UI display changes to solve empty session/turn columns; the source normalized event fields need to be correct first.

### 3. Add row summary and pair metadata in core/server

Add an additive row contract:

```ts
readonly pairIdx: number | null;
readonly summary: string;
```

Keep `payloadPreview` temporarily only if needed for a low-risk migration, but do not render it as `Payload` after this phase.

Implement deterministic summary priority in core projection:

1. parse error;
2. JSON-RPC error response;
3. correlated success response with request method;
4. `resourceList` URI/resource;
5. delta/content;
6. tool call/result;
7. notification;
8. generic request/response;
9. unknown action/method fallback.

Cap summaries at 160 characters, render through React text only, and redact path/token-like arg values.

For pair metadata, compute `pairIdx` from the existing `Correlator.pairOf(idx)` path in `AppState.buildRow()`. Update late-response patch logic to compare and patch `pairIdx` in addition to status/latency so both earlier request rows and later response rows know their pair.

### 4. Rework timeline row rendering

Update the timeline grid to the approved UI-SPEC order:

```ts
export const TIMELINE_GRID_COLUMNS =
  "4px 96px 96px 16px 44px 220px 132px 72px 72px minmax(240px, 1fr)";
```

Remove the main-row `StatusCell`, remove `ActionDot`, render ID first after the rail, and render `Summary` last. Add inline badges/rails for `ERR`, `AUTH`, `TIMEOUT`, and `ORPHAN` so error/warning states remain clear without a standalone status column.

### 5. Pair highlight in timeline

Compute selected pair state from stable event indices, not virtual item indices. In `TimelineList`, find the selected row’s `pairIdx`, check whether that index is present in the current visible/filter/grouped items, and pass pair-highlight/hidden-pair props to `EventRow`.

Required attributes:

- `data-selected="true"` on selected row;
- `data-pair-highlight="request"` or `"response"` on the counterpart row;
- `data-pair-hidden="request"` or `"response"` on selected row when the pair is filtered out.

Do not fetch detail just to discover pair highlight. Detail correlation metadata remains useful, but row highlight should be immediate.

### 6. Pretty JSON expansion

Raise the default `PrettyJsonView` expansion from the current shallow rule to the UI-SPEC minimum:

```ts
shouldExpandNode={(level: number) => level < 5}
```

Keep the existing truncation cap and Raw tab behavior.

## Common Pitfalls

- **Pair highlight via detail fetch:** would be delayed and inconsistent; project `pairIdx` into rows instead.
- **Forgetting retroactive pair patches:** earlier requests must receive `pairIdx` when later responses arrive.
- **Display-only session/turn fix:** UI changes cannot populate fields if parser extraction misses nested real-log paths.
- **Summary privacy leaks:** content/message/args can contain sensitive text; cap, redact, and use synthetic fixture content.
- **Removing status without replacement:** add `ERR`/`AUTH`/`TIMEOUT`/`ORPHAN` badges and accessible labels.
- **Leaving forbidden action copy in aria/title:** remove `ActionDot` from rows and add negative tests for `family unknown` strings.

## Open Questions

None blocking. Planner should choose whether to commit a synthetic fixture only or a minimal real-derived scrubbed fixture after privacy review. The safer default is synthetic fixture content that mirrors real structural shapes.
