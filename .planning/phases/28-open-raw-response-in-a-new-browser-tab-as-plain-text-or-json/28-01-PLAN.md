<objective>
Let the user open the selected event's raw payload in a new browser tab, as
either pretty-printed JSON (application/json) or plain text (text/plain), from
the detail-pane actions menu.

Purpose: Inspecting large payloads inline is cramped; opening the raw content in
a dedicated browser tab lets the user use the browser's own find/scroll/JSON
rendering. The app is local-first (no network, no CDN), so the tab must be
backed by a same-origin Blob URL — never an uploaded/hosted resource.

Output: An `openInNewTab` helper plus two new menu items in CopyMenu, with unit
tests covering MIME type, content, popup-blocked handling, and URL revocation.
</objective>

<task name="Add an openInNewTab helper and wire it into CopyMenu">

1. Create packages/ui/src/components/detail/openInNewTab.ts exporting:

   ```typescript
   export function openInNewTab(text: string, mime: "application/json" | "text/plain"): boolean
   ```

   It must:
   - Build `const blob = new Blob([text], { type: mime });`
   - Create `const url = URL.createObjectURL(blob);`
   - Open it with `const win = window.open(url, "_blank", "noopener,noreferrer");`
   - Schedule revocation so the tab can load first:
     `setTimeout(() => URL.revokeObjectURL(url), 60_000);`
   - Return `win !== null` (false signals a blocked popup). If `win` is null,
     still revoke (you may revoke immediately in that branch).
   - No `dangerouslySetInnerHTML`, no network calls, no #hex literals.

2. In CopyMenu.tsx, add two menu items after the existing copy items. Because
   these open tabs rather than copy text, add them as their own entries with an
   `open` handler (do NOT shoehorn them through `handleCopy`, which writes to the
   clipboard). Each handler:
   - Closes the menu (`setOpen(false)`).
   - Serializes `const text = (() => { try { return JSON.stringify(event.raw, null, 2); } catch { return "[Circular or non-serializable value]"; } })();`
   - Calls `openInNewTab(text, mime)` with `application/json` (JSON item) or
     `text/plain` (text item).
   - On success calls `onCopy("Opened in new tab", true)`; on false calls
     `onCopy("Popup blocked — allow popups to open in a new tab", false)`.
   - Labels: "Open in new tab (JSON)" and "Open in new tab (text)".

   Keep the existing copy items unchanged. Render the new items in the same
   `role="menu"` list with `role="menuitem"` and the same styling.

3. Extend CopyMenu.test.tsx with tests (jsdom) that:
   - Stub `URL.createObjectURL` to return a sentinel and capture the Blob;
     stub `URL.revokeObjectURL`; spy `window.open` (returns a truthy object).
   - "Open in new tab (JSON)": clicking the item calls `window.open` with the
     sentinel URL and `"_blank"`, the captured Blob has `type` `application/json`,
     and `await blob.text()` equals `JSON.stringify(rawData, null, 2)`.
   - "Open in new tab (text)": same but Blob `type` is `text/plain`.
   - Popup-blocked: when `window.open` returns null, `onCopy` is called with
     `ok === false`.

   Run `pnpm -F @ahp-inspector/ui exec vitest run src/components/detail/CopyMenu.test.tsx`
   until green.

Do NOT change DetailPanel.tsx, PrettyJsonView, RawJsonView, or the JSON_STYLES
mapping. The only product changes are the new helper and the two menu items.
</task>
