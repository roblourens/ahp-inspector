<objective>
Build the two presentational React components from the UI-SPEC: `DropOverlay` (full-viewport
state-driven drop affordance) and `MultiFileToast` (bottom-right transient notice). Both are
pure presentational components — they accept state as props and emit user intent via
callbacks. No drag-event listeners, no fetches, no parser calls — those live in Plan 03.

Purpose: Honor the UI-SPEC's six-pillar sign-off (locked copy, locked tokens, locked layout,
locked accessibility) by making each rule independently testable on a stub-driven component
before the integration wiring lands. Keeping the components stateless makes the AppShell
wiring in Plan 03 a thin state machine plus `<DropOverlay state={...} />`.

Output:
- `packages/ui/src/components/drop/DropOverlay.tsx` + test
- `packages/ui/src/components/drop/MultiFileToast.tsx` + test
</objective>

<interfaces>
Both components are presentational. Public shapes:

```typescript
// DropOverlay.tsx
export type DropOverlayState =
  | { kind: 'idle' }
  | { kind: 'armed'; replacing: boolean }
  | { kind: 'error'; message: string };

export function DropOverlay(props: {
  state: DropOverlayState;
  onDismiss: () => void;        // called on Esc keypress while in 'error' state
}): JSX.Element | null;

// MultiFileToast.tsx
export function MultiFileToast(props: {
  basename: string;             // already-extracted filename, never an absolute path
  ignoredCount: number;         // > 0 (caller does not render the toast otherwise)
  onDismiss: () => void;
}): JSX.Element;
```

Inline-styled React only. No CSS modules, no styled-components, no shadcn. Mirrors the
existing pattern in `packages/ui/src/components/picker/ManualOpenInput.tsx` and
`packages/ui/src/components/picker/LogPickerPanel.tsx`.

Locked copy (verbatim from 17-UI-SPEC.md "Copywriting Contract"):
- Armed heading (no active log): `Drop a .jsonl file to open.`
- Armed body (no active log):   `Drag from Finder, Explorer, or VS Code's file tree.`
- Armed heading (replacing):    `Drop to replace the active log.`
- Armed body (replacing):       `The current log will close and the new file will start tailing.`
- Error message — no file URI:  `That drop didn't include a file path. Try dragging from Finder or VS Code's file tree, or paste a path in the picker below.`
- Error message — wrong ext:    `Only .jsonl files are supported. Drop the raw AHP log file.`
- Error — server reject:        Plan 03 supplies these from `ManualOpenInput`'s existing `ERROR_COPY` table.
- Toast text:                   `Opened {basename}. Ignored {N} other file{s}.` (s only when N > 1)
- Toast dismiss aria-label:     `Dismiss notice`

The `state.message` on the error variant is whichever of the two error variants (or a
server-error string) the parent has selected — DropOverlay does not pick the copy, it
displays whatever the parent passes. The parent (Plan 03) is responsible for handing in
the verbatim strings above.
