<objective>
Create a pure, DOM-free parser that turns a `DataTransfer` payload into either a usable
filesystem path string or a typed error code. This is the entire path-acquisition logic
for Phase 17 (CONTEXT D-02 + D-04) extracted from any React/DOM concerns so it can be
unit-tested without jsdom event simulation.

Purpose: D-02 ("text/uri-list first, friendly error otherwise") and D-04 ("first .jsonl
wins") are the load-bearing rules for the whole phase. Locating them in a single pure
function means the overlay component (Plan 02) and the integration wiring (Plan 03) can
both rely on a single source of truth that has its own test surface.

Output:

<interfaces>
The parser is consumed by Plan 02 (DropOverlay) and indirectly by Plan 03. Public shape:

```typescript
// parseDroppedUri.ts
export type ParseResult =
  | { kind: 'ok'; path: string; ignoredCount: number }
  | { kind: 'error'; code: 'no-uri' | 'not-jsonl' };

/**
 * Turns a DataTransfer payload into either a usable absolute filesystem path
 * (decoded from a file:// URI) or a typed error code.
 *
 * Reads ONLY `text/uri-list` (the standard cross-app MIME type). Does not touch
 * `dataTransfer.files`, `text/plain`, or any other channel — those are intentionally
 * out of scope per D-02.
 */
export function parseDroppedUri(
  dataTransfer: Pick<DataTransfer, 'getData'>,
): ParseResult;
```

Note the parameter type uses `Pick<DataTransfer, 'getData'>` (not the full `DataTransfer`)
so tests can pass a tiny `{ getData: (mime: string) => string }` stub without constructing
a real `DataTransfer` instance (jsdom's `DataTransfer` is incomplete).
</interfaces>

  <behavior>
    - Input: an object exposing `getData(mime: string): string` (the relevant slice of `DataTransfer`).
    - Read `getData('text/uri-list')`. If empty string or only whitespace → return `{ kind: 'error', code: 'no-uri' }`.
    - Split by `\r?\n`. Drop blank lines and lines starting with `#` (these are RFC 2483 comment lines).
    - Iterate the remaining URIs in order. For each entry:
      * Parse with `new URL(entry)` inside a try/catch; URLs that throw are skipped (count toward `ignoredCount`).
      * Skip if `url.protocol !== 'file:'` (count toward `ignoredCount`).
      * Decode the path with `decodeURIComponent(url.pathname)`.
      * Skip if the decoded path does not end (case-insensitive) with `.jsonl` (count toward `ignoredCount`).
      * Otherwise this is the winner — return `{ kind: 'ok', path: decodedPath, ignoredCount }` where `ignoredCount` is the number of valid-list entries that were skipped before this winner. (Comment / blank lines do NOT count toward `ignoredCount`; only entries that were considered and rejected do.)
    - If no winner is found AND at least one valid-list entry existed → return `{ kind: 'error', code: 'not-jsonl' }`.
    - If no valid-list entries existed at all (only blanks/comments) → return `{ kind: 'error', code: 'no-uri' }`.
  </behavior>
  <action>
Create `packages/ui/src/components/drop/parseDroppedUri.ts` exporting the `ParseResult` discriminated union and the `parseDroppedUri` function described above.

Implementation notes (per D-02 / D-04 in 17-CONTEXT.md):
- Use a single `getData('text/uri-list')` call. Do NOT also read `text/plain` or `dataTransfer.files` — that is intentionally out of scope for this phase.
- The case-insensitive `.jsonl` check must use `.toLowerCase().endsWith('.jsonl')` (not a regex) so a single-pass implementation stays obvious.
- Trim each non-empty line before parsing — Finder, Explorer, and VS Code all emit a trailing `\r` on macOS/Windows.
- `ignoredCount` only counts valid-list entries that were considered and rejected (bad URL parse, non-file protocol, non-.jsonl extension). It does NOT count blank lines or `#` comment lines. UI-SPEC's toast copy reads "Opened {basename}. Ignored N other files." — N is the number of additional file-like things in the same drop, not the number of header lines in the MIME payload.
- Per Rob's preference, no `any` and no unsafe casts. The parameter type `Pick<DataTransfer, 'getData'>` keeps tests trivial without sacrificing type safety.
- No comments in the file beyond a single one-line module header that names CONTEXT decisions D-02 and D-04 for the next reader.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01-01 | Tampering | parseDroppedUri | mitigate | Use `new URL(...)` in a try/catch — any malformed URI is silently skipped, never returned. No string concatenation into the resolved path. |
| T-17-01-02 | Information disclosure | parseDroppedUri | mitigate | Function never throws or returns the original raw URI on failure paths — only the typed error codes `no-uri` / `not-jsonl`. Callers cannot accidentally surface attacker-supplied URIs to the user (Phase 11 trust posture, T-04-03-02). |
| T-17-01-03 | Spoofing | parseDroppedUri | accept | A drag from a hostile site could supply a `file://` URI for a path the user did not intend; the eventual `POST /api/sessions/open` is rate-limited and validated server-side (`packages/host-node/src/host-adapter.ts`).
