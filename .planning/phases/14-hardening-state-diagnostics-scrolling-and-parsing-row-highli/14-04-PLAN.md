<objective>
Make search navigation feel native: Enter / Shift+Enter from the focused search input cycle matches (matching the existing F3 behavior), and the timeline scrolls the current match into view.

Purpose: F3 navigation already exists, but the muscle-memory key (Enter) does nothing while the user is typing in the search box, and after a match is "selected" the row may be off-screen in the virtualizer.
Output: Enter/Shift+Enter wired and reliable scroll-to-current-match.
</objective>

<interfaces>
From `TimelineRegion.tsx`, the existing search-nav listener:

```ts
function onSearchNav(e: Event): void {
  const direction = (e as CustomEvent<"previous" | "next">).detail;
  if (direction === "previous" || direction === "next") selectSearchMatch(direction);
}
window.addEventListener("ahp-search-nav", onSearchNav);
```

So the canonical way to trigger match navigation from anywhere in the UI is:
`window.dispatchEvent(new CustomEvent("ahp-search-nav", { detail: "next" | "previous" }));`
