  <behavior>
    - First valid call to `stateAtIndex(1)` computes replay and returns `cache.hit === false`.
    - Second valid call to the same exact index returns `cache.hit === true`, `cache.size === 1`, and an equal replay result.
    - With `maxEntries = 2`, calls for indexes `0`, `1`, `2` evict index `0`; calling `0` again is a miss.
    - Cache entry for index `1` remains a hit after `store.append(...)` adds a later event at index `2`.
    - `reset()` clears all cached entries and the next valid call is a miss.
    - Invalid/out-of-range calls return replay diagnostics but are not cached.
  </behavior>
  <action>
    Create `packages/server/src/state-replay-index.ts` exporting:
    - `export interface StateReplayCacheInfo { readonly hit: boolean; readonly size: number; readonly maxEntries: number; }`
    - `export interface StateReplayIndexResult { readonly result: ReplayResult; readonly cache: StateReplayCacheInfo; }`
    - `export class StateReplayIndex { constructor(store: EventStore, maxEntries = 25); reset(): void; stateAtIndex(targetIndex: number): StateReplayIndexResult; }`

    Implementation requirements:
    - Import `EventStore`, `ReplayResult`, and `replayToIndex` from `@ahp-inspector/core`.
    - Keep a private exact-index cache: `#cache = new Map<number, ReplayResult>()`.
    - Use exact numeric `targetIndex` as the cache key; do not cache by resource.
    - Treat valid cacheable indexes as `Number.isInteger(targetIndex) && targetIndex >= 0 && targetIndex < this.#store.size()`.
    - For invalid/out-of-range indexes, call `replayToIndex(this.#store.events, targetIndex)` so diagnostics remain visible, but do not store the result.
    - For cache hits, refresh LRU recency by deleting and re-setting the key.
    - For cache misses, compute `replayToIndex(this.#store.events, targetIndex)`, store it, and evict the oldest inserted key while `#cache.size > #maxEntries`.
    - `cache.size` in returned metadata must reflect the cache size after the operation.
    - Do not modify `packages/core/src/replay.ts`.

    Create `packages/server/src/state-replay-index.test.ts` using Vitest and synthetic `AhpEvent` objects patterned after `packages/core/src/replay.test.ts`. Include tests named with these exact substrings:
    - `returns cache miss then hit for the same exact target index`
    - `evicts least-recently-used exact indexes when maxEntries is exceeded`
    - `keeps cached historical indexes stable across append`
    - `clears cached results on reset`
    - `does not cache invalid or out-of-range indexes`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| JSONL log input -> AppState replay | Untrusted local log content is parsed and replayed through canonical reducers. |
| AppState replay cache -> HTTP route consumers | Reconstructed state may contain log-derived content and must remain local/lazy. |
| Live tail rotation -> cache lifecycle | Log replacement changes the event index universe and invalidates replay results. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-08-01-01 | Tampering | `StateReplayIndex.stateAtIndex` | mitigate | Only replay immutable `EventStore.events` up to exact `targetIndex`; invalid/out-of-range requests are not cached. |
| T-08-01-02 | Information Disclosure | `SsePayload` / `EventRow` | mitigate | Keep reconstructed state behind `AppState.stateAtIndex`; tests assert SSE rows do not contain `state`, `resources`, `diagnostics`, `intents`, or `cache`. |
| T-08-01-03 | Denial of Service | Replay cache | mitigate | Bound cache to `maxEntries = 25` exact-index entries with LRU eviction. |
| T-08-01-04 | Information Disclosure | Log metadata | mitigate | Preserve basename-only `LogMeta`; no absolute path fields are added. |
| T-08-01-05 | Tampering | Rotation reset | mitigate | Clear replay cache in the same reset block as store/correlator/search/rows. |
</threat_model>
