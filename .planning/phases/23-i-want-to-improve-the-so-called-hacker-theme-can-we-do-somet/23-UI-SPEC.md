# Phase 23 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; use the repo-owned token/global CSS theme system |
| Preset | not applicable |
| Component library | none |
| Icon library | lucide-react, unchanged |
| Font | Inter Variable for UI, JetBrains Mono Variable for log/data surfaces |

Source contract: Phase 23 extends the existing `data-theme="hacker"` theme path, `tokens.css`, and shared global styling. It does not introduce shadcn, a new theme runtime, a renderer rewrite, or component-local Hacker branches when a shared theme-layer implementation can carry the effect.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps and existing CRT grid rhythm |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Reserved viewport-safe framing allowance when the CRT frame needs a large layout-safe inset |

Exceptions: Phase 23 adds no new ordinary layout density. Preserve existing shipped dimensions including the 12px intermediate spacing token, 28px timeline row height, 40px header/filter rhythm, responsive detail rail/drawer geometry, and minimum 44px drawer close hit target. CRT rim, vignette, scanlines, noise, fringe, and warp padding may use effect-specific tokens because they are compositing values rather than layout spacing.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 | 1.5 |
| Row / compact UI | 13px | 400 | 20px fixed row rhythm |
| Body | 14px | 400 | 1.5 |
| Heading | 16px | 600 | 1.2 |

Typography is structurally unchanged by the CRT overhaul. Phosphor glow, fringe, displacement, and glass shading may alter rendered character feel in Hacker, but the underlying text sizes, weights, truncation, focus outlines, and native selectable DOM text remain intact. Only the existing two weights, regular 400 and semibold 600, are allowed.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#020704` | Hacker viewport background, tube depth, dark edge falloff |
| Secondary (30%) | `#06120a` with raised `#0a1b10` | Existing surfaces, panels, menus, shell depth, CRT glass body |
| Accent (10%) | `#39ff88` | Theme-consistent phosphor glow, scanline tint, Hacker focus/selection emphasis, edge-energy highlights |
| Destructive | `#ff4f7b` | Existing destructive/error semantics only; never repurpose it as CRT decoration |

Accent reserved for: selected row emphasis, focus rings, existing active theme/menu treatments, intentional phosphor/glow accents, scanline tint, and bounded Hacker-only CRT edge energy. Edge-weighted chromatic separation may borrow existing Hacker secondary signal colors such as cyan/purple only as a compositing artifact at viewport edges; it must not recolor core semantic statuses or split every glyph uniformly.

Color scope is Hacker-only. Dark and Light remain visually clean and must not inherit CRT filter references, animated CRT keyframes, glass overlays, or new effect-token defaults.

## Visual Hierarchy Contract

1. The CRT overhaul is a whole-screen Hacker identity, not a local panel flourish. Header, source strip, filter surfaces, timeline, desktop detail rail, responsive detail drawer, menus, drop overlays, toast surfaces, and status bar must read as content inside one physical display.
2. The display hierarchy is: unchanged product content and hit targets; rendered-surface warp for the shared Hacker display surface; pointer-transparent analog overlay stack; dark tube/frame edge treatment above or around the screen read. The implementation may choose exact selectors, but this visual order is locked.
3. The warp must be visibly curved-glass and felt across the full screen, not only corner shading. It may be bounded after feasibility testing, but the initial contract is intentionally bold rather than restrained.
4. The analog stack must visibly include stronger scanlines, glass/vignette shading, tube rim or enclosed dark edge treatment, phosphor glow, fine noise, edge-weighted chromatic fringe, and occasional signal instability. These layers should reinforce one material read rather than look like unrelated stickers.
5. Product hierarchy still wins inside the CRT. Selection, focus-visible outlines, semantic warning/error colors, timeline readability, detail JSON inspection, and existing menu states remain distinguishable after compositing.

## Compositing And Layering Contract

| Layer | Required Intent | Interaction Rule |
|-------|-----------------|------------------|
| Shared display surface | Carry the true rendered-surface curved warp for Hacker | Must contain the intended full app presentation in standalone and webview, with attachment point validated against fixed overlays |
| Decorative scan/noise/glass layers | Add scanlines, noise, vignette, grid/glass shading, and signal beats | Always `pointer-events: none`; never trap hover, click, wheel, drag/drop, or focus |
| Tube frame / edge darkness | Make the viewport feel physically enclosed | May crop/fade edges visually, but may not hide actionable controls or silently reduce reachable hit areas |
| Glow/fringe | Add phosphor bloom and edge-weighted RGB separation | Preserve readable text centers and semantic color meaning; strongest fringe stays toward display edges |
| Existing product overlays | Theme menu, detail drawer/backdrop, picker, drop overlay, and toast | Must remain visibly part of the CRT screen while preserving their current z-order, viewport coverage, and dismiss behavior |

Implementation may use shared CSS plus an inline/in-bundle SVG filter definition if the feasibility slice proves it. No remote textures, fetched filter maps, CDN assets, or outbound dependencies are allowed.

---

## Motion And Comfort Contract

| Mode | Contract |
|------|----------|
| Default motion | Restless analog life: continuous low-level drift plus occasional visibly noticeable signal beats/glitches. Motion is ambient and should not react to hover, scroll, selection, focus, or typing. |
| Reduced motion | Preserve static CRT identity: fixed warp, tube edge, static glass/vignette, static scanline/noise/fringe impression as appropriate. Remove animated drift, pulses, signal beats, glitches, and any animated filter-map modulation. |
| Performance posture | Prefer cheap overlay opacity/transform choreography for ongoing motion. Animated displacement is allowed only if it survives responsiveness verification against the Phase 22 large-log posture. |

The contract deliberately separates static CRT identity from temporal instability. `prefers-reduced-motion: reduce` must not flatten Hacker back into Dark, and it must not leave residual animation running.

## Interaction Safety Contract

Rendered filter warp changes paint, not DOM hit-testing. The contract therefore requires implementation to treat visual/interactive divergence as a product risk, not merely a screenshot concern.

| Interaction | Required Safety Check |
|-------------|-----------------------|
| Theme picker | Trigger remains visually honest, keyboard navigable, dismissible, and usable under Hacker warp. |
| Timeline rows | Hover, selected row emphasis, and click selection continue to align acceptably with the visible row position. |
| Search/filter controls | Text entry, focus-visible ring, filter buttons, and chip dismiss actions remain visually and mechanically trustworthy. |
| Responsive detail drawer | Backdrop still fills the viewport, close button remains reachable, Escape remains valid, and the drawer is not clipped or visually detached by filter containing-block behavior. |
| Desktop detail rail | Resize/view surfaces remain legible and aligned with their actual interaction geometry. |
| Log picker, drop overlay, toast | Existing layering and close/dismiss behavior survive the display-surface attachment point. |

Any displacement strength that makes controls appear materially offset from their actual hit areas is outside contract, even if it looks dramatic. Start aggressive visually, then reduce displacement or alter attachment strategy if verification shows dishonest targets.
