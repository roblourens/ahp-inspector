# Phase 4 — UI Design Contract: Live Tail, Discovery, and Persistence

> Visual and interaction contract for Phase 4. Generated by gsd-ui-researcher.
> Consumed by gsd-planner (implementation tasks), gsd-executor (visual source of truth), gsd-ui-auditor (retroactive comparison).

---

## Phase Summary and UX Goals

Phase 4 makes the viewer feel like a live local tool. A user can launch with no file, discover VS Code / Copilot AHP log files, pick one or type a path, watch events arrive in real time, pause their reading position without losing incoming traffic, and return to the same view state on reload.

**UX goals for this phase:**
1. Zero-friction entry: no-arg launch drops the user into a discovery picker that lists candidates immediately — never a dead screen.
2. Live without distraction: new events appear but don't yank the user away from where they were reading.
3. Safe by default: no absolute paths appear on any UI surface.
4. Transparent state: every major state transition (no log, paused, rotation, watch error) has a distinct, unambiguous affordance.
5. State as memory: per-log filter/search/grouping/scroll state is remembered across reloads, silently degrading when stale.

## Screen / State Inventory

The Phase 4 `Connection` type is extended to: `"connecting" | "connected" | "disconnected" | "no-server" | "no-log"`.

| State | `connection` value | Trigger | Top-level component |
|-------|--------------------|---------|---------------------|
| Server not running | `"no-server"` | `/api/log/meta` probe returns non-2xx or network error | `ServerNotRunningState` (existing, unchanged) |
| **No active log** | `"no-log"` | `/api/log/meta` returns 204 | `NoActiveLogState` (new, full-page) |
| Connecting | `"connecting"` | SSE opened; awaiting `snapshot-end` | `LoadingState` inside `AppShell` (existing) |
| Active log — has events | `"connected"` | SSE stream live with rows | `AppShell` (existing, extended) |
| Disconnected | `"disconnected"` | SSE drops after being connected | `DisconnectedBanner` inside `AppShell` (existing) |
| Watch error | `"disconnected"` + `lastWatchError` set | `watch-error` SSE frame | `WatchErrorBanner` (new, replaces `DisconnectedBanner` content when error present) |
| Rotation/truncation | `"connecting"` (briefly) after SSE reset | `rotation` SSE frame | `RotationBanner` (new, transient, inside `TimelineRegion`) |

> **Hard rule:** "no log" and "no server" must be visually and copy-level distinct. "Server not running" uses existing design. "No active log" is a full-page picker with discovery content — never blank.

- Primary focal point: `CandidateList` is the main visual anchor on the picker screen; it occupies the largest vertical region and appears before manual open so the newest likely log is fastest to scan.

### 2. CandidateRow layout

Each row is a single horizontal flex container, height `--candidate-row-height` (36px):

```
[●] [basename.jsonl (mono)]  [origin chip]  [2h ago]  [4.2 KB]  [›]
 ▲         ▲                      ▲             ▲          ▲      ▲
 confidence  --font-mono           badge        mtime      size   chevron
 dot         --text-row-size      12px caps    muted 12px  muted 12px  reveal
```

Column widths (flex, no fixed px except dot):
- Confidence dot: 8px circle, `--space-4` total left cell
- Basename: `flex: 1`, min-width 0 (truncates with ellipsis), monospace, 13px semibold
- Origin chip: fixed min-width 80px, right-aligned in its slot
- mtime: 64px, right-aligned, 12px muted
- Size: 56px, right-aligned, 12px muted
- Chevron `›`: 16px icon, muted

Hover: `background: var(--color-surface-raised)`
Focus: `outline: 2px solid var(--color-accent); outline-offset: -2px`
Active/pressed: `background: var(--color-chip-bg-active)`

**No absolute path text anywhere in the row.** The `id` is an opaque string; the basename comes from `SafeCandidate.displayLabel`.

### 3. HeaderBar extensions (active log)

Right zone gains two controls between existing theme picker and version badge:

```
[…existing brand left…]  [⏸ Pause] [↗ Switch log]  [🎨 theme]  v{version}
```

- **Pause/Play toggle** (`LivePauseButton`): `--row-height` (28px), chip style matching theme picker. Icon: `Pause` (lucide) when live-following, `Play` when paused. Background becomes `color-mix(in srgb, var(--color-accent) 15%, var(--color-surface))` when paused, with `--color-accent` text/icon.
- **Switch log** (`SwitchLogButton`): `--row-height` (28px), secondary chip style. Text: "Switch log". Opens `LogPickerPanel`. If collapsed to icon-only at narrow widths, retain `aria-label="Switch log"`.

Both controls are only rendered when `connection === "connected" || connection === "connecting"`.

Active-log metadata label (basename + event count + session count) can optionally appear in the left zone of `HeaderBar` between the brand and the right controls — max width 240px, truncate with ellipsis. Text: `{basename}  ·  {N} events  ·  {S} sessions` at `--text-ui-muted-size`, muted color.

### 4. LogPickerPanel (non-modal overlay)

Triggered by "Switch log" button. Slides in from the top as an inline dropdown (not a full-page takeover). This preserves the current log view behind it.

```
┌─ panel overlay (top: 40px, left: 0, right: 0, max-height: 60vh) ─┐
│ ┌─ panel header ──────────────────────────────────────────────┐  │
│ │ "Switch log"  (semibold)                         [✕ Close]  │  │
│ └─────────────────────────────────────────────────────────────┘  │
│ ┌─ same content as NoActiveLogState (no heading) ─────────────┐  │
│ │ CandidateList + ManualOpenInput                              │  │
│ └─────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

- `z-index: 800` (below HeaderBar theme menu at `z-index: 1200`).
- Background: `var(--color-surface)`, `border-bottom: 1px solid var(--color-border-strong)`.
- Close on Escape, close on backdrop click (click outside panel area below the HeaderBar row), close on successful log open.
- When panel is open, the timeline below is dimmed: `opacity: 0.35; pointer-events: none`.

### 5. NewEventsPill

Positioned **inside `TimelineRegion`**, fixed to the bottom center, 16px from the inner-bottom edge of the timeline scroll area:

```
         ┌──────────────────────────────────┐
         │  ↑  12 new events · Resume Following ↑  │
         └──────────────────────────────────┘
```

- `position: absolute; bottom: var(--space-4); left: 50%; transform: translateX(-50%)`.
- Container `TimelineRegion` must be `position: relative`.
- Only rendered when `livePaused === true && pendingNewCount > 0`.
- Height: 28px, `border-radius: 14px` (pill).
- Background: `var(--color-pill-bg)` (new token), border: `1px solid var(--color-pill-border)`.
- Text: `{N} new events · Resume Following` — "Resume Following" in `var(--color-accent)`.
- When `pendingNewCount >= 100`: display "99+ new events · Resume Following".
- Clicking: calls `clearPendingNewCount()`, sets `livePaused = false`, scrolls `virtualizer` to `rows.length - 1`.

### 6. RotationBanner

Displayed inside `TimelineRegion` above the list (between filter bar and virtual list area) for 5 seconds after a `rotation` SSE frame, then auto-dismisses.

Height: 32px. Left rail: 3px `var(--color-banner-rotation-fg)`. Background: `var(--color-banner-rotation-bg)`.

Content: `[⚠ icon]  Log rotated — reloading from new file.`  (no dismiss button; auto-clears).

### 7. WatchErrorBanner

Replaces `DisconnectedBanner` content (or overlays it) when `lastWatchError` is set.

Height: 40px (matches `DisconnectedBanner`). Left rail: 2px `var(--color-destructive)`.

Content: `[✕ icon]  Watch error: {errorCode}  ·  [Retry Connection]  [Reopen log]`

- "Retry Connection" calls `connectLogStream()` (existing reconnect path).
- "Reopen log" posts `POST /api/sessions/open` with the current log's id, resetting the file tail from the start.
- Error code shown is the SSE frame's `code` field (`"read-error"` → display `"file read error"`, `"watch-fatal"` → display `"watcher stopped"`). Never echo the raw OS error string to the UI.

## Interaction Contracts

### Keyboard

Phase 3 reserved: `/` (search focus), `f` (filter bar), `Esc` (close detail/clear search), arrow keys, `Home`/`End`, `Page Up`/`Page Down`.

Phase 4 additions:

| Key | Context | Action |
|-----|---------|--------|
| `Space` | `TimelineRegion` focused, not inside a text input | Toggle pause/resume (`setLivePaused(!livePaused)`) |
| `Esc` | `LogPickerPanel` open | Close panel |
| `Enter` | `CandidateRow` focused | Open that candidate |
| `Enter` | `ManualOpenInput` path field | Submit path (same as clicking "Open Log") |

> `Space` must be guarded: only fire when `document.activeElement` is within `TimelineRegion` (or is `body`/`#root`), not when focus is in `SearchInput`, `ManualOpenInput`, or any other input.

### Focus management

- When `LogPickerPanel` opens: focus moves to the first `CandidateRow` if candidates exist, otherwise to the `ManualOpenInput` text field.
- When `LogPickerPanel` closes: focus returns to `SwitchLogButton`.
- When `NoActiveLogState` mounts: focus moves to first `CandidateRow` if candidates exist, otherwise to `ManualOpenInput`.
- `NewEventsPill` is keyboard-focusable (`tabIndex={0}`) with `role="button"`. Arrow-key navigation in `TimelineRegion` must not skip over it (pill is outside the virtualizer DOM).

### Accessibility

- `CandidateList`: `role="list"`, each `CandidateRow` is `role="listitem"` with a `<button>` inside. Do not make the row itself a button — wrap inner action in `<button>` to satisfy biome `useSemanticElements`.
- `LivePauseButton`: `aria-label="Pause live follow"` / `"Resume live follow"` based on state.
- `LogPickerPanel`: `role="dialog"`, `aria-modal="false"` (non-modal), `aria-label="Switch log"`. Traps focus with a focus guard only loosely (non-modal; Esc still closes).
- `NewEventsPill`: `role="status"` for the count, `role="button"` on the resume action. `aria-live="polite"` wrapping the count so screen readers announce when new count changes.
- `RotationBanner` and `WatchErrorBanner`: `role="alert"` for immediate announcement.
- `ManualOpenInput` error region: `role="alert"` and linked via `aria-describedby` to the input.

All Phase 4 components use only CSS variable tokens. When Phase 5 adds overrides to `[data-theme="light"]` and `[data-theme="hacker"]`, the new Phase 4 tokens will automatically inherit correct values without modifying Phase 4 components.

## Responsive Behavior

Phase 4 targets the same laptop-width baseline as Phases 2–3. Full responsive is Phase 5. Minimums for Phase 4 layout:

- `NoActiveLogState` content: max-width 640px, centered. Collapses gracefully below 640px by removing the max-width constraint (full-width with `--space-4` horizontal padding).
- `LogPickerPanel`: max-height `60vh`, scrollable. Works at any viewport width.
- `CandidateRow`: baseline layout at ≥400px viewport. Origin chip hides below 480px (`display: none`) to prevent overflow; mtime hides below 360px.
- `HeaderBar` controls: `SwitchLogButton` text collapses to icon-only (`FolderOpen`, 14px) below 600px viewport width and retains `aria-label="Switch log"`.
- `NewEventsPill`: always visible at any width; truncates pill text to "N new · Resume Following" below 360px.

## Privacy Constraints

These are hard requirements enforced at the component boundary.

1. **`CandidateRow` must not receive or render a `path` prop.** The `SafeCandidate` type passed to the component omits `path`. The `id` is an opaque server-generated hash.
2. **`ManualOpenInput` error copy must never include the user's typed path.** Error messages are pre-written strings indexed by server-returned `code`. If the server returns an unexpected `code`, fall back to the generic error string.
3. **`HeaderBar` active-log label uses `basename` only.** Comes from `LogMeta.filename` (already basename-only per existing server convention).
4. **`LogPickerPanel` and `NoActiveLogState` list sections must be labelled "Discovered logs," not "Recent paths" or any label implying absolute paths are shown.**
5. **`localStorage` persistence stores only UI prefs (filter state, grouping, scroll, search query, detail width).** Never stores log content, raw payload fragments, or absolute paths. The `logKey` (opaque hash) is used as the storage key — it is non-reversible.
6. **Rotation/watch-error banner copy must not include filesystem paths or OS error strings.** Map server `code` to display-safe strings as defined in the Copywriting Contract.

## Non-Blocking Recommendations

1. **LogPickerPanel vs full-page:** The non-modal panel approach (slide-from-top) is specified because CONTEXT.md D-19 says "feel like part of the current polished shell." If the panel feels visually heavy, planners may substitute a narrower right-side drawer (360px) — this does not affect the interaction contract, only layout.

2. **"Follow latest" toggle:** RESEARCH.md §5.3 mentions `followLatest: boolean` as a store flag. This spec defers the explicit toggle UI to Phase 5 polish; default is `true` (auto-follow on resume). The store field should be added in Phase 4 for persistence but no toggle button needs to be wired in the header yet.

3. **G6 (stat poll fallback):** RESEARCH.md §3.2 marks the `fs.stat` polling fallback for network filesystems as optional with an env-flag gate. This spec does not require a UI element for it in Phase 4. If implemented, surface it as a `WatchErrorBanner` variant when polling detects a missed change — no new UI needed.

4. **Candidate confidence scoring algorithm:** CONTEXT.md notes exact scoring is at the planner's discretion. The UI contract only requires the three tiers (high / medium / low) and their corresponding dot colors and badge labels. Planners choose the scoring formula.

5. **Refresh cadence:** Auto-refresh of discovered candidates is not specified; a manual "Refresh List" button is required. If planners add auto-refresh (e.g. every 30s while picker is open), the UI should show a subtle spinner inside the "Refresh List" button during the fetch, not a full reload of the list.

## Open Design Questions

*(Non-blocking; planners resolve before implementation)*

1. **`CandidateRow` keyboard navigation:** Should `CandidateList` use `role="listbox"` + `option` for Up/Down arrow navigation within the list, or plain `role="list"` with standard Tab? Recommendation: `role="listbox"` + roving tabIndex for a more keyboard-native picker feel — but either satisfies accessibility requirements.

2. **Active-log label in `HeaderBar` left zone:** The spec suggests showing `basename · N events · S sessions`. If the basename is long (e.g. `agenthost.20250507T142311.789.jsonl`), this truncates aggressively at 240px. Alternative: show only the basename, push counts to a `<title>` tooltip. Planners should decide based on the real fixture filename length.

3. **Rotation recovery UX:** The spec says rotation auto-reconnects (sets `connection = "connecting"`, reopens SSE). If the rotated file is gone before reconnect, the user will see `WatchErrorBanner`. Should `RotationBanner` show a "Reopen log" fallback button if the reconnect fails within 5s? Recommend yes, but this is a planner call.
