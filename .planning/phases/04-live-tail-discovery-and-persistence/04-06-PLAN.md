  <behavior>
    - On store transition where `logKey` becomes non-null AND rows.length transitions 0 → N (snapshot-end fired): call loadForLogKey(logKey) and apply the prefs (filters, columns, groupCollapsed). selectedIdx is applied only if `0 ≤ selectedIdx < rows.length`; otherwise dropped.
    - After hydration, subscribe to subsequent store changes; debounce 250ms; serialize {filters, columns, selectedIdx, groupCollapsed} → saveForLogKey(logKey, prefs).
    - groupCollapsed entries trimmed to 1000 entries (FIFO) before save.
    - On `resetForLogSwitch()` (logKey changes to a new value): persist the OLD logKey first (immediate flush, not debounced), then re-hydrate for the NEW logKey on next snapshot-end.
    - Quota error from saveForLogKey is swallowed; persist disables itself until next page load.
  </behavior>
  <action>
Implement `usePersistEffect()` as a React hook that:

1. Reads `logKey`, `rows.length`, and a snapshot version counter from the store.
2. Tracks `currentLogKey` in a ref. On `logKey` change AND `rows.length > 0` transitioned from 0 (i.e. snapshot-end just fired):
   - Call `loadForLogKey(logKey)`. If non-null, set filters/columns/groupCollapsed via store actions (`setFilters`, `setColumns`, `setGroupCollapsed`). If `selectedIdx != null && selectedIdx < rows.length` then `setSelectedIdx(selectedIdx)`.
3. After hydration (or if no prefs), subscribe to store changes via `useAppStore.subscribe`. On each change, schedule a debounced save (250ms timer reset on each change):
   - Build prefs object; trim groupCollapsed to last 1000 keys; call `saveForLogKey(logKey, prefs)`.
4. On `resetForLogSwitch` (detected as logKey transition from non-null to non-null OR null→non-null after non-null), flush the previous logKey synchronously before subscribing for the new logKey.
5. Guard with a `disabled` flag: any caught error from save sets `disabled=true` and stops further saves.

Mount the hook from AppShell.tsx top level (a single instance per app):

```tsx
export function AppShell(): JSX.Element {
  usePersistEffect();
  // ... existing
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store ↔ localStorage | UI process; no cross-origin |
| paused buffer ↔ append | server-controlled append rows are buffered, not dropped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | DoS | pendingBuffer growth while paused | mitigate | Buffer is bounded only by client memory in practice; pause UI is intentional. Cap groupCollapsed to 1000 keys to prevent unbounded persistence. |
| T-04-06-02 | DoS | localStorage quota | mitigate | LRU 50 logKeys, groupCollapsed cap 1000, save errors swallowed and persistence disabled. |
| T-04-06-03 | Information Disclosure | localStorage `ahp-log-prefs-v1` | accept | Only filter/column/idx/group state — no log contents, no paths. logKey is sha256 (no path). |
| T-04-06-04 | Tampering | hydrated selectedIdx out-of-range | mitigate | Range check before applying; otherwise drop silently. |
| T-04-06-05 | Confused state | persist effect double-mount | mitigate | Single mount in AppShell; React StrictMode double-effect tolerated by debounce + idempotent save. |
</threat_model>
